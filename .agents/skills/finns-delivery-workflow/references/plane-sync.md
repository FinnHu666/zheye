# Plane 同步协议

先读根 AGENTS.md 与 [现有 Plane 工作流](../../../../docs/PLANE_WORKFLOW.md)。本规范不修改 OAuth、MCP 审批策略或工作区的权限。

## 0. 同步何时确认：G1 → G2

新需求评审通过后、实际产品原型制作前，AI 必须主动处理同步检查点，而不是等待用户再问“更新到 Plane 了吗”。先核对本地基线及已有映射，再列出待同步内容。产品范围批准与管理写入批准分开记录。

- 用户本轮已要求操作 Plane/给出工作项：按授权范围读取最新对象、去重并整理可审阅差异，随后对每个写操作确认；没有自动写入。
- 没有对应 Plane 指令：先用本地已通过需求整理“待登记/更新清单”，目标项目、对象和状态无法核实时写明未核实，主动询问是否授权核对并同步。获得明确指令后再连接，补齐实际差异并逐项确认写入。不得绕过根约定自动查询，也不得把未核实的清单当成已同步。
- 每项差异明确标题、对象、范围/验收、当前→目标状态及保留字段。允许同组问题分别确认多个具体操作，不用笼统同意代替。

检查点结束条件：

1. **已同步并回读**：远程管理内容与当前评审基线一致。
2. **核对后无需变更**：已同步的内容确实一致，保留核对证据，不再要求相同写入确认。
3. **用户明确延期/不使用 Plane**：记录来源、待同步范围及后续节点，按已授权范围继续原型。
4. **工具不可用且用户明确先继续**：记录失败及待补，继续可获授权的原型；不是悄悄绕过检查点。

尚未回答不是延期授权。等待所需决定时可整理原型任务、素材与其他已授权独立工作；实际原型制作按上述检查点处理结果进入。用户在同一指令明确要求“先制作原型、Plane 稍后补”等时已构成延期决定，不重复询问。普通问答、小修复或无管理差异的任务不机械触发此检查点。

在原型确认、范围变更、开始实施、验收或发布等造成管理内容/状态变化的节点再次提出相应差异。检查点是过程要求，不增设 Plane 自定义状态，也不把每阶段内部检查都变成远程写入。

## 1. 读取与去重

仅当用户要求操作 Plane、或给出工作项时连接。核实工作区、项目 ID/描述、工作项标题/正文/状态/验收、最新更新时间及可用状态。按已知映射、标识符、关键词搜索，必要时查活动/归档及分页；记录查询范围，不能把第一页没有结果说成全库不存在。

真实执行项目须经指定。示例项目不收真实需求。目标未确定时先在已确认收件箱记录，描述目标版本和待决事项；创建新项目、Release、关联对象各自是写操作，不因“排期”自动创建。不要臆造负责人、截止日期或高级字段。

## 2. 写前提供具体差异

为每个操作分配 P01、P02…，记录：

- action、对象/project/workitem ID 或待创建对象的名字；
- 当前值→目标值、保留字段、管理状态依据、需求映射及验收摘要；
- 新建时的去重结论；更新时保留人工原文，只增补明确内容；
- 证据位置及未完成项；仅使用已核实可访问的远程 URL，仓库路径标为路径，不伪装成远程链接。

根约定为“任何 MCP 写操作均须本轮用户明确提出并逐次确认”。每个具体操作单独确认；可在同一组问题逐项列出各操作，各项均须得到明确回答，不能以一个笼统“全部同步”代替具体差异。用户已经明确确认的同一操作不重复询问；新增操作或差异发生实质变化需单独确认。

新增/更新/评论/附件/关联/状态/归档/删除/Release/项目等都算写操作。“resolve”若可能创建对象也算写操作。读操作失败不授权换成创建；调用 skill 本身不授权远程写入。

## 3. 执行与回读

1. 收到该操作的明确确认；记录来源、时间和所确认差异修订。
2. 写前重读最新对象。已变化则重新计算差异；影响原确认内容时重新确认，不能覆盖他人新内容。没有 API 条件更新时，说明存在读写间并发窗口。
3. 每次只执行已确认操作。发生超时/不明确返回时先查询是否已成功，尤其新建项不得盲目重试。
4. 按返回 ID 回读，核对对象归属与目标字段；状态、正文及关联分别检查。服务端可能规范化 HTML 容器/属性，应比较内容和字段是否完整保留，不能只用原始 HTML 字符串判断成功。仅收到成功返回而没回读时记录“调用成功，回读未确认”。
5. 在本地同步回执记编号/ID、差异、确认、调用/回读结果及证据，更新需求映射；不保存完整工具响应、令牌或远程正文镜像。

管理状态以 Plane 为准，本地记录最后核对时间。计划/原型/代码/技术验证/真人验收/发布各自表述，不能因文档完成把业务工作项设 Done。映射到 Plane 自有状态须先读实际状态；没有对应状态时用描述补充，不自动新建工作流。

## 4. 失败和未授权

MCP 未连接、缺权限、对象不存在、冲突或用户尚未确认时，标记“待同步/失败/结果不明确”。继续本地不依赖它的已授权资料工作；在 G1→G2 转换中，实际原型是否继续按第 0 节处理，不凭“已授权本地工作”自动跳过节点。不通过网页、脚本或其他凭据绕过确认规则。下一轮先核对待同步记录和远程当前值，不能假设以前调用未成功。

没有确认时给用户明确的待写差异及规则来源，不将其写成已更新。不向 Plane 上传原始私聊、含个人资料截图或模型完整输入输出；上传脱敏材料也须作为独立具体操作确认。
