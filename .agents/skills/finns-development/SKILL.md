# FINNS 开发流程

这是随项目保存的 skill 源文件。由根目录 AGENTS.md 引导读取，不依赖个人记忆或全局安装。仅规划时输出可执行方案，不实施业务变化。

## 建立本轮边界

读项目根目录 AGENTS.md、VERSION、CHANGELOG.md 和相关源码。读 docs/NEXT_ITERATION_PLAN.md 的对应需求；接手先读 docs/AI_HANDOFF.md。先检查 Git 状态，目录不是仓库时如实记录，不把没有 Git 当作没有用户改动。

用需求 ID 表达本轮目标、可观察验收条件和排除项。区分用户明确要求与方案假设。简单修复无需扩写整套设计；跨数据模型、路由或身份边界的变化先补充方案决定。

## 统一协作与状态协议

先识别本轮模式，不能把“记录/规划”默认为实施授权：

- 规划：更新需求与执行方案，列出验收和待决事项；不改业务代码、不连接/迁移业务数据库。
- 实施：只做用户授权的范围；遇到会改变数据归属、权限边界、外部服务或发布范围的未决选择时先停在该决策点。
- 诊断/答复：提供证据和结论；未经要求不顺手修改。

每个需求记录一个稳定 ID、用户原意、方案假设、非目标、状态和可观察验收条件。状态统一为“已记录 / 待用户确认 / 待实施 / 实施中 / 已实施 / 验收通过 / 暂缓”。“已实施”表示变更已完成，不代表验收通过；“验收通过”须有可追溯证据且与当前源码相符。若本轮沿用历史验收而未复跑，明确标出历史证据及本轮未复验项。计划完成不等于功能上线，构建通过也不等于运行态或用户流程通过。

收到与历史需求相似的请求时，先对照需求 ID、当前源码和验收证据，判断它是既有需求重申、已有功能回归还是新的差异；沿用原 ID 更新状态，只有真实新增范围才追加新 ID。不得把已经实现的同一需求重新写成待开发，也不得因旧记录称“完成”而忽略源码回归。

实施按可独立验证的小闭环推进：核对现状与影响面 → 确定接口、数据、路由、权限及回退方式（只对相关部分）→ 实现 → 执行匹配风险的验证 → 检查最终改动范围 → 更新需求状态、CHANGELOG 与交接。新增测试应能在对应行为回归时失败；选择单元、集成、浏览器或真实 PostgreSQL 验证，以改动风险和本项目约定为准，不为流程本身机械地跑无关检查。

交接必须让未读本轮对话的下一位 AI 能继续：写清当前事实、已完成与未完成、改动文件、验证命令及结果、未执行的检查、数据库/服务是否被触碰、下一步和所需用户决策。最后回复也分开说明实际改动、验证证据和限制；不要把推测或计划写成事实。

## 实施时保持的项目约束

- 保留 Java 17 + Vue 3 基线；不要照旧 DEVELOPMENT_PLAN.md 重建项目。保持 FINNS 名称和现有界面语言。
- 导航新增独立 Vue Router 路由，同时检查 Java SpaController 的刷新回退。个人身份来自服务端会话，不能信任客户端传来的 ownerId。
- 数据库变更采用可审计迁移；PostgreSQL 接入后由 Flyway 管理结构、Hibernate validate 校验。数据库产品、实例和版本是三项独立选择，连接成功前不得宣称已迁移。
- 迁移真实数据先有可恢复备份和演练记录。保留旧 ID、密码哈希、时间和关联；无法确认归属的旧数据列入待处理清单，不能凭昵称猜用户。
- 私人 Skills 清单与一般个人中心分开授权。新增个人接口按用户过滤，普通登录不能获得本地文件信息。
- 缺少本机工具时，优先使用用户指定的 D:/E: 路径或项目局部方案；未经明确授权，不在 C: 盘安装运行时或服务。便携式数据库须限制监听地址、标注仅开发用途并把数据放进已忽略的数据目录。
- 前后端接口先约定路径、请求/响应 DTO、分页、错误与权限，再按小功能闭环修改；不要直接序列化含密码哈希的用户实体。

## 按改动选择验证

- 文档：验证引用文件、相对链接、需求与完成状态，无需重跑全部业务测试。
- 页面：构建 Vue；浏览器验证交互、桌面和移动视口、直达刷新及截图。未做视觉检查就标明。
- 身份与个人数据：正常登录/退出、未登录、用户 A 访问 B、会话过期；涉及 Cookie 写请求还要验证 CSRF 策略。
- 数据库：在目标 PostgreSQL 验证建库迁移、重复启动、约束、分页和恢复；H2 测试通过不能代替 PostgreSQL 验证。
- PostgreSQL 写入集成测试使用 `scripts/test-postgres.ps1 -DatabaseName <isolated-database>`；脚本只允许 `finns_test_*` 或 `finns_restore_check_*`、仅连接 `127.0.0.1`，拒绝对 `finns` 主库运行。测试数据保留在指定隔离库，不自动 drop。
- 使用现有 scripts/test.ps1、scripts/package.ps1；发版前先构建 frontend，因为当前 package.ps1 不构建 Vue。
- 当前 PowerShell 脚本可能未传播原生命令失败状态，需检查 npm/Maven 的真实退出码及结果；完善脚本时显式检查 LASTEXITCODE。
- 不以界面成功提示替代服务端持久化证据，不用实现文字匹配测试替代行为测试。

## 记录与交接

改动记入 CHANGELOG.md 的 Unreleased，只有实际发版才同步四处版本。更新 docs/AI_HANDOFF.md：已完成、未完成、变更文件、验证命令/结果、运行实例、下一步、阻塞条件。重大架构选择记录原因和替代方案；不要重复堆积互相冲突的规则。

向用户说明结果、验证和实际限制。构建成功不等于运行服务已加载新资源；交付访问链接前检查当前服务内容。不得因本 skill 自动获得部署、远程写入或破坏性迁移权限。

若修改本 skill，保持其项目专属触发范围和用户授权边界；验证 frontmatter、引用链接及项目流程入口。涉及触发条件或操作边界的实质改动，应使用一个适用的 FINNS 请求和一个相邻但不应触发的请求做行为检查；不以标题或措辞匹配代替流程验证。
