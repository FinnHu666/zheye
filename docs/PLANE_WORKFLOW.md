# Plane 与 FINNS 本地开发协作

Plane 是独立的需求和项目管理系统；本机 Codex 用户级配置及 FINNS 仓库的项目级配置连接 Plane Cloud。Plane 负责需求收集、优先级和项目安排；FINNS 仓库负责技术方案、源码改动和验收证据。不要把账号令牌或需求正文复制进仓库。

需求同步、开发交付与 AI 产物归档统一使用 [finns-delivery-workflow](../.agents/skills/finns-delivery-workflow/SKILL.md)。阶段门禁、写前差异/逐项确认/回读和归档模板各有独立参考；不因引入 skill 自动获得远程写入或部署权限。2026-10-10 下一版本安排与实际写入回执见 [0.7.0 同步记录](iterations/0.7.0/PLANE_SYNC.md)。

## 同步确认的节点

新需求评审通过后、实际产品原型制作前，AI 主动提出 Plane 同步清单及所需授权/具体差异，不等用户再次询问。连接和逐项写入继续遵守 AGENTS；没有对应指令时先整理本地清单、标明远程未核实，再发起询问，不能自动查询或写入。

正常处理为“已同步并回读”或“核对后无需变更”，再进入原型；用户明确延期/不使用 Plane，或明确允许连接失败时先继续，也可记录待补后推进。无答复不是延期许可。等待期间允许整理原型资料和任务书，不把它们说成实际制作。后续管理内容/状态真正变化时再确认相应差异，不对无变化反复审批。完整规则以 [Plane 同步协议第 0 节](../.agents/skills/finns-delivery-workflow/references/plane-sync.md) 为准，案例分析见 [本轮流程修正](requirements/FINNS-REQ-015-018_PROCESS_FIX.md)。

## 本地任务接续规则

- 用户提供 Plane 工作项编号或链接时，先通过 MCP 读取标题、描述、当前状态和验收条件，再按根 `AGENTS.md` 确认本轮逐项写入授权；不要根据编号猜需求。
- 开始实现前，在 `docs/NEXT_ITERATION_PLAN.md` 记录本地需求 ID 与 Plane 工作项编号/链接，并把实施范围和验收条件落入项目文档。沿用现有需求 ID，避免在 Plane 与本地重复建项。
- 本地文档保留技术设计、文件/接口影响、命令结果、未执行检查、部署边界及人工验收状态。Plane 记录面向管理的状态和本地文档链接；本地证据未验证前不得把 Plane 项目标为完成。
- AI 可按用户要求新增“待评估”项、搜索和整理描述。决定采纳、排期、删除、关闭或完成前，先取得本轮用户指令；MCP 写操作也必须逐次确认。
- 如果 Plane MCP 未连接，不假称已查询或已写入。仍可按现有 FINNS 流程在本地继续获授权的代码工作，并把 Plane 同步标记为未完成。
