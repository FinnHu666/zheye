# FINNS 零代码专题创建与导入方案

设计日期：2026-10-02；实施更新：2026-10-03。需求：FINNS-REQ-012。状态：第一阶段已实施，技术验证通过；真人易用性目标待验证。

第 1–9 节保留设计和评审背景；当前实现、验证和运行边界以第 10 节为准。

## 1. 用户目标与范围

用户希望把租房经验、服务注册流程、锻炼计划、各类总结快速整理为可自定义专题，即使不懂编程也能创建、导入和复用。

产品建议：以“粘贴内容 → 整理预览 → 保存专题”为主流程，以场景模板和复制已有专题为辅助入口。底层统一使用专题、章节、内容卡片；普通用户不接触 JSON、数据库字段或 Markdown 语法。

实施采用的方案：默认私人草稿，公开分享由作者主动操作；已有资料导入比凭空生成优先；不使用 AI 也能完成核心流程。用户已要求按本方案实施代码与版本记录。

非目标：首期不做网站搭建器、任意字段数据库、多人协作、健康数据追踪、自动网页抓取或 AI 自动发布。主库部署与远程发布不在本轮代码实施范围。

## 3. 用户流程

### 3.1 首屏三个入口

- **我有现成内容**（首选）：粘贴笔记、聊天内容或文章文字，也可上传 TXT/Markdown。无需先填多项表单。
- **从模板开始**：选择租房经验、操作教程、周期计划、经验复盘或空白专题。显示一个真实结构预览和填写示例。
- **复用我的专题**：复制自己已有内容，或仅使用章节结构；生成独立私人草稿，不影响原专题。

“只输入一句话，让 AI 帮我整理”作为后续可选增强，不成为创建必经步骤。

### 3.2 导入流程

1. 粘贴原文或选择文件。文字区提供示例，原文始终可回看。
2. 点击“整理成专题”。根据标题、编号和段落识别章节及内容，展示建议名称、目录、正文与待处理项。
3. 用户直接改标题、合并/拆分段落、移动条目；可以退回“整篇保留”。只有专题名称为创建的必要用户输入，其他信息可选或由原文提取。
4. 点击“保存到我的专题”。事务创建私人草稿，进入编辑页。再次点击或网络重试不得重复建专题。
5. 点击“预览”确认阅读效果；想分享时再点“发布”。私人专题可长期保留，无需强制发布。

规则解析不承诺理解语义：没有可靠标题时保留整段或按长度建议拆分，不能默默删内容、补事实或把一句话扩写成教程。复杂聊天记录先保留发言顺序，再由用户整理。自动编号只用于阅读显示，不反复写入标题。

### 3.3 编辑与自定义

默认只显示标题和内容，展开后才看到来源、适用范围与备注。首期编辑区提供纯文本段落、列表预设和独立链接卡片；工具栏式富文本和强调在第二阶段实现。删除可撤销，上下移动为基础，拖拽为后续辅助。桌面左侧目录、右侧编辑，移动端单列并可切换目录。

模板是可删改的起点，不锁定章节数量或领域。添加按钮使用“写一段经验 / 加一个步骤 / 加一份清单 / 放一个链接”等普通用语。首期步骤与清单可保存为 NOTE 预设并提供合适编辑控件；不声称已有读者勾选或跨设备进度功能。

### 3.4 持续补充资料

已有专题编辑页提供“导入补充资料”，复用同一导入预览流程。首期默认追加为新章节，显示“将新增 X 章、Y 条，原有内容保留”；不自动替换原章节或按相似标题合并。用户可在预览中调整后确认，提交携带目标专题 revision，冲突时保留本次导入内容供重新预览。重复文本可提示，但不自动删除。专题当前有未保存编辑时，先完成保存或让用户保留导入预览，不能用追加覆盖本地输入。

这项能力纳入第一阶段，避免第一次创建方便、后续补充又回到逐条录入。对于没有可靠标题的材料，按钮与反馈称为“按段落整理”；只有可选 AI 才承担语义归类，规则解析不自动猜测哪些段落属于“踩坑”。

## 4. 一套能力覆盖不同领域

| 场景 | 建议章节 | 个性化方式 |
| --- | --- | --- |
| 租房经验 | 我的需求、找房渠道、看房、签约、入住、复盘 | 城市、预算等以可编辑说明/清单呈现；复制后替换自己的内容 |
| 服务注册教程（如用户提到的 Claude） | 适用地区与条件、准备事项、操作步骤、常见问题、来源与核验日期 | 作者填写适用范围和依据；界面不预置未经核验的注册结论 |
| 锻炼计划 | 目标与条件、每周安排、动作说明、执行记录模板、阶段复盘 | 用户填写频次、时间和限制；本方案不生成具体医疗或训练处方 |
| 经验复盘 | 背景、目标、做法、结果、踩坑、下次怎么做 | 保存成自己的模板，下次只需改内容 |

首期用章节与笔记表达安排、对比和复盘；后续若真实使用需要，再增加原生表格、作者定义的清单、步骤卡片。领域名称是模板标签，不增加租房/健身等专属业务表。

变化快的教程可设置“作者最后核验日期、适用范围、参考来源”，核验日期与系统更新时间分开；编辑文字不能自动刷新为“已核验”。本方案仅设计内容结构，没有查询或验证任何服务当前的地区支持政策。

## 5. 导入、复用与可移植性

第一阶段支持粘贴纯文字、UTF-8 TXT/Markdown，建议限制单次 1 MiB（服务端同样限制）。保留标题、顺序、文本与链接。Markdown 图片先显示引用及未导入提示，不下载图片；表格等暂不支持的结构原样保留并提示，不伪装为成功转换。

超过现有 50 章、500 条、单条正文 4000 字限制时，预览中给出拆分建议及超限位置；总量仍超限则阻止提交并保留输入，绝不截断。规则识别的所有拆分均可回看原文并撤销。

“整篇保留”表示保持原文顺序和内容，不表示绕过单条长度限制；长文拆成连续编号的笔记并在确认前展示。首期原文只留在当前导入会话内存供对照，完成导入或退出后释放，不另行保存原文件；离开未完成流程提示并提供复制原文。跨刷新自动恢复不是首期承诺。正文写入后的正常持久化与原文件存档是两回事。

第二阶段支持本人专题“另存为模板”和 FINNS 专题文件导入/导出。普通用户只看“导出专题”“导入专题”，内部格式带 schemaVersion，包含元数据、章节、条目、来源及模板版本，不包含账号信息与读者状态。站内文章引用跨实例不能复用裸 ID，导出为带来源的链接；本人同实例复制才保留有权限的 POST 引用。文件导入不会接受 ownerId、发布状态或原数据库主键。

模板复制出独立实例，模板升级不覆盖已有专题。只复制结构时移除正文及个人信息；保留示例必须由模板作者明确设置。首期只复用本人内容；他人专题的复制授权另定，公开可读不自动等于允许整篇复制。

Word/PDF 解析、图片上传/OCR、网页抓取放后续。它们分别涉及版式、扫描识别、附件与网络抓取，不能把“支持导入”描述成支持所有文件。

## 6. 技术落点（实施草案）

沿用 Java 17、Spring Boot 3.3.x、Vue 3、PostgreSQL，不更换技术栈。

- 复用 `/me/collections/new` 三入口；新增 `/me/collections/import` 导入预览、`/me/collections/:id/preview` 私有预览。同步 Vue Router 与服务端 SPA 刷新回退验证。
- 统一内部 Document DTO，规则解析、模板复制和以后 AI 生成都产生相同结构，经同一个校验器后保存；避免三套编辑器。
- 草稿与发布分别校验：私人草稿允许简介为空、空章节和未填完的 NOTE/LINK 占位项；公开发布要求有效内容，并逐项标出待补内容，不自动丢弃。当前 DTO/validateEntry 要求非空简介、NOTE 正文和有效 URL，实施须同步调整草稿契约与持久化约束。卡片简介缺省时可显示原文摘要或“暂无简介”，不虚构总结。
- 建议接口：`POST /api/me/collection-imports/preview`（只解析，不创建专题）；`POST /api/me/collection-imports/commit`（编辑后的文档 + 幂等键，创建草稿）；`POST /api/me/collections/{id}/duplicate`（本人内容/结构复制）。服务端重新校验所有预览结果，不能信任客户端。
- 补充导入建议使用 `POST /api/me/collections/{id}/imports`，接收预览后的文档、revision 和幂等键；只能追加到本人工作稿，复用保存校验、单事务与幂等机制。
- 幂等键按用户隔离，并关联请求摘要；相同键和相同请求返回原结果，键相同而内容不同返回冲突。导入提交为单事务，失败不留下半个专题。
- 权限沿用 Session、CSRF、后端归属验证；URL 继续只允许 http/https，导入文本不执行 HTML/脚本，不自动请求外部 URL。解析接口同样要求登录并限量。
- 发布隔离建议增加带 schemaVersion 的不可变发布文档快照，公开页读当前发布快照，编辑器读工作稿；发布前校验并原子切换快照。公开列表、计数、摘要和引用也须统一读已发布版本，避免只隔离正文。这是内容发布快照，不宣称已实现完整历史版本恢复。
- 发布快照覆盖 ContentController 的目录/详情/文章列表、CollectionWorkspaceController 的 outline、PersonalController 的自选专题展示；私人“我的专题”仍读工作稿。SiteStatsController 当前统计全部专题，须改为仅统计有效公开专题，私人草稿和归档不增加公开计数。公开排序使用发布更新时间，自动保存不使公开列表上浮。
- PersonalController 的旧收录/移除接口目前直接写 collection_entries，touch() 仅更新日期而不递增 revision。实施时统一进入工作稿写服务，纳入 revision 冲突保护；禁止旧入口绕过发布隔离。发布动作先等待保存队列排空，再发布确认过的 revision，发布与归档并发也须校验版本。
- 发布快照中的 POST 保留文章 ID 和发布时的卡片标题/摘要；文章详情仍为原文的当前版本，不将引用文章全文纳入专题冻结。引用失效时显示不可用，不返回越权内容。迁移为已有公开专题建立基线快照并核对目录/数量/顺序，归档立即关闭公开读取，重新公开必须显式发布。
- 当前章节/条目保存采用删除重建，ID 不稳定。导入首期不要依赖其 ID 做长期进度；后续清单进度须先实现稳定 blockId、增量更新及删除语义。
- 模板首期可作为项目内置版本化配置；个人模板再新增归属用户、模板版本和文档快照的持久化表。后续结构变更追加 Flyway，实施时检查最新版本号，不修改 V6。
- 自动保存按本地编辑序号串行提交。服务端响应只确认对应序号，不覆盖更新的本地输入；新编辑继续排队。失败/409 保留用户输入，给出重试或差异处理，不以刷新丢弃用户内容。私有本地恢复若启用，需按用户隔离并在退出时清理。

AI 增强需要后续确定供应商、费用和资料发送范围。只在用户主动使用时发送选定内容；生成的补充与原文分开标记，失败后回到规则解析。保留“只整理不扩写”选项，不将模型推测写成已核验事实。

## 7. 分阶段交付与验收

### 第一阶段：最低可用闭环（优先）

粘贴/TXT/Markdown → 整理预览 → 修改 → 私人草稿 → 阅读预览 → 主动发布；支持向本人专题追加导入，提供四类场景模板、本人专题复制，并修正保存及公开版本隔离。无外部 AI 依赖。

实施顺序：A. 草稿宽松校验、保存队列和私有预览；B. 新建/追加导入、内置模板与本人复制；C. 发布快照、所有公开读入口与旧写入口收口。三项组成第一阶段交付，A/B 单独完成不算公开发布流程验收通过。

### 第二阶段：形成可复用工具

个人模板、FINNS 文件导入导出、有限富文本及原生步骤/清单卡片。根据实际使用确定是否需要对比表或周期表，不默认引入公式或复杂字段系统。

### 第三阶段：按需要增强

可选 AI 整理、Word/PDF/OCR、附件、读者进度。每项独立范围与验收，不包含在第一阶段承诺里。

### 可观察验收（目标，尚未执行）

1. 租房、注册教程、锻炼计划、经验复盘四份样例无需代码或专用领域模型，都能创建、改名、增删章节和预览。
2. 邀请 5 位非技术用户，从提供的 800–1500 字材料开始；至少 4 位无协助在 3 分钟内保存并预览可读专题。记录卡点；这是待验证的可用性目标，不是已达到结果。
3. 标题/编号、无标题、长文本、混合链接、不支持结构、乱码及超限输入都有明确结果；原文段落能逐项对照，无静默丢失或凭空补事实。
4. 连续编辑跨越保存响应、保存失败重试、双标签页 409、路由离开、重复导入提交均不静默丢字或重复建专题。
5. 用户 A 不能预览、导入覆盖或复制用户 B 的私人专题；私有内容不出现在公开 API。发布后继续编辑，公开版本保持不变，主动更新发布后才变化。
6. 复制专题不改变来源，清单/原文顺序保留；移动端 390px 可完成全流程，新路由直达刷新正常。
7. 实施需要 Vue 构建、针对性行为测试、隔离 PostgreSQL 迁移与浏览器验证；执行证据见第 10 节。
8. 空白模板只填名称即可保存；未完成条目可以保存并明确提示待补，发布时才执行完整校验。逐项验证与当前 DTO/数据库约束兼容。
9. 向有内容的专题追加导入后，原文不变、新增顺序正确；重复提交一次生效，版本冲突不丢导入材料，公开版本保持不变。
10. 公开广场、自选专题、公开详情/outline/文章列表、首页专题计数均只反映发布版本；旧收录/移除接口与编辑器并发会触发 revision 冲突，不静默覆盖；归档后所有公开入口不可读。
11. 对现成材料与从零填写模板分别观察任务完成情况。3 分钟目标仅适用于材料已经准备好的导入任务，不包含编写经验本身的时间；自动化测试不能代替非技术用户试用。
