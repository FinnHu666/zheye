# FINNS 专题工作台方案

状态：FINNS-REQ-011 验收通过。记录日期：2026-10-02；实施与验收日期：2026-10-02。

本文件定义“更方便地制作专题”的产品和技术方案，并记录已完成的实现与验证。

## 1. 目标

把现有“标题 + 简介 + 文章集合”升级为可编辑的知识路线，让同一套专题能力覆盖：

- 步骤指南：例如租房准备、筛选房源、看房、签约、入住复盘。
- 阅读路线：例如动漫作品的入门、主线、外传、延伸阅读。
- 资源清单：例如按用途整理工具、网站、VPS 或学习资料。
- 自定义专题：作者从空白结构开始自由组织。

用户应能先保存草稿，再逐步补充和排序，预览无误后发布；不要求先写完多篇文章才能建立专题。

## 2. 当前差距

当前源码事实：

- `community_collections` 只有名称、简介、作者和时间等基础字段。
- `collection_posts` 只能收录站内文章，并按加入时间倒序展示；没有作者定义的步骤顺序、章节和条目说明。
- 创建入口位于 `/me/collections`，表单只有名称和简介；创建后没有独立编辑工作台。
- 公开详情 `/collections/:id` 使用文章卡片网格，无法表达“第一步、第二步”或“入门、主线、扩展”的路线结构。
- 当前后端只允许作者把自己的站内内容加入专题。这个限制应在升级时保持，除非以后单独确认允许收录他人的站内内容。

因此不能只给现有表单增加几个输入框；需要一个统一、有序且可扩展的专题文档模型。

## 3. 产品模型

### 3.1 专题格式

专题保存 `format`，可选：

- `GUIDE`：步骤指南。默认章节为“准备 / 执行 / 检查 / 复盘”。
- `READING_PATH`：阅读路线。默认章节为“入门 / 主线 / 扩展 / 回顾”。
- `RESOURCE_LIST`：资源清单。默认章节为“必备 / 按场景选择 / 补充资料”。
- `CUSTOM`：空白专题，不预置章节。

模板只负责生成可编辑的初始骨架，不锁死作者。作者可以改名、删除、添加和重新排序章节。

### 3.2 专题状态

- `DRAFT`：仅作者在工作台可见，不出现在专题广场、自选专题或公开直达接口。
- `PUBLISHED`：公开可见，可加入自选专题。
- `ARCHIVED`：作者保留内容但停止公开展示；第一期可只提供归档，不做物理删除。

现有专题迁移后统一标为 `PUBLISHED`，避免升级后从公共页面消失。

### 3.3 章节与条目

一个专题包含有序章节，每个章节包含有序条目。条目统一支持三种来源：

- `NOTE`：作者直接写的步骤、说明或建议，支持有限 Markdown；适合“签约前核对合同”等简短内容。
- `POST`：引用作者自己已发布的 FINNS 文章或话题，保留站内详情链接和作者信息。
- `LINK`：外部链接，包含标题、URL 和作者补充说明；适合动漫资料页、政策页面或工具资源。

章节顺序和条目顺序决定公开阅读路线。编号由顺序自动生成，不写死在标题中。

第一期不保存读者的勾选进度。步骤中的清单可先用 `NOTE` 的 Markdown 列表表达；个人进度属于后续独立需求。

## 4. 创作流程

### 4.1 页面与路由

- `/me/collections`：我创建的专题。增加状态标签、“继续编辑”“预览”和“新建专题”。
- `/me/collections/new`：选择模板并填写专题名称、卡片简介、目标读者和专题目标。
- `/me/collections/:id/edit`：专题工作台。桌面端为大纲 + 编辑区，移动端改为单列步骤式编辑。
- `/collections/:id`：公开阅读页。改为章节目录和有序路线，不再只是无顺序卡片网格。

新增前端路由后须继续由 `SpaController` 的 `/me/**` 与 `/collections/**` 回退支持直达和刷新。

### 4.2 工作台交互

1. 选择“步骤指南 / 阅读路线 / 资源清单 / 空白专题”。
2. 填写名称、简介、目标读者和希望读者完成什么。
3. 系统生成章节骨架；作者可添加、重命名、删除和上下移动章节。
4. 在章节内添加笔记、自己的站内文章或外部链接，并补充“为什么推荐 / 这一项要注意什么”。
5. 页面自动保存草稿，并明确显示“保存中 / 已保存 / 保存失败”。失败时保留本地未提交内容并允许重试。
6. 预览后发布。发布前检查名称、简介、至少一个章节和至少一个有效条目。

第一期排序使用明确的上移/下移按钮并支持键盘，确保移动端和无障碍可用；拖拽可作为增强，但不能成为唯一排序方式。

## 5. 数据方案

实施时新增 append-only Flyway V6，不修改 V1–V5：

### `community_collections` 新字段

- `format varchar(24)`：`GUIDE / READING_PATH / RESOURCE_LIST / CUSTOM`。
- `status varchar(16)`：`DRAFT / PUBLISHED / ARCHIVED`。
- `audience varchar(160)`：目标读者，可空。
- `goal varchar(300)`：读完后的预期结果，可空。
- `revision bigint`：编辑并发版本，初始 0。
- `published_at timestamp with time zone`：首次或最近发布时刻，可空。

保留现有 `name` 和 `description` 作为公开卡片标题与短简介。

### `collection_sections`

- `id`、`collection_id`、`title`、`description`、`sort_order`、创建/更新时间。
- 每个专题最多 50 个章节；`(collection_id, sort_order)` 唯一。

### `collection_entries`

- `id`、`collection_id`、`section_id`、`kind`、`sort_order`。
- `title`、`annotation`、`body` 用于自定义标题、推荐理由和笔记正文。
- `post_id` 仅 `POST` 使用；`external_url` 仅 `LINK` 使用。
- 每个专题最多 500 个条目；`(section_id, sort_order)` 唯一。
- 数据库约束保证条目类型与必填字段匹配；`post_id` 建外键和查询索引。

### 兼容迁移

- 现有专题全部设为 `PUBLISHED / CUSTOM`。
- 每个已有专题创建“专题内容”默认章节。
- 按当前页面实际显示顺序 `collection_posts.created_at DESC, post_id DESC` 将已有关系回填为 `POST` 条目，保持升级前的视觉顺序和数量。
- V6 先保留 `collection_posts` 作为回退依据；应用切换到新模型并完成验证前不删除旧表，也不同时维护两套写入源。

## 6. API 契约

编辑器以“整个草稿文档”原子保存，减少大量细碎接口和半保存状态：

- `POST /api/me/collections/drafts`：按模板创建草稿，返回专题 ID、初始章节和 `revision`。
- `GET /api/me/collections/{id}/draft`：读取作者自己的完整编辑文档。
- `PUT /api/me/collections/{id}/draft`：提交元数据、章节和条目；请求带 `revision`，服务端在单事务中校验、更新并返回新版本。
- `POST /api/me/collections/{id}/publish`：执行发布校验并发布。
- `POST /api/me/collections/{id}/archive`：归档专题。
- `GET /api/me/posts?q=&type=&page=&size=`：编辑器选择本人内容时使用，继续保持分页。
- `GET /api/collections/{id}`：公开元数据；仅 `PUBLISHED` 可匿名访问。
- `GET /api/collections/{id}/outline`：返回章节和公开条目。站内文章返回摘要引用，外链和笔记返回安全展示字段。

原 `POST /api/collections` 与 `/api/collections/{id}/posts` 在迁移期保留兼容，但新页面只使用新 API；确认无消费者后再另立需求废弃，不能在 V6 中直接移除。

`PUT draft` 遇到旧 `revision` 返回 409 和当前版本，不得静默覆盖另一标签页中的编辑。

## 7. 权限与安全

- 创建、读取草稿、编辑、发布和归档均以服务端 Session 中的 user ID 判断所有权，不接受客户端 owner ID。
- 未发布专题匿名访问返回 404；其他登录用户访问编辑接口返回 403。
- `LINK` 只接受规范化后的 `http` 或 `https`，拒绝 `javascript:`、`data:`、本地文件和空主机；前端外链使用 `rel="noopener noreferrer"`。
- Markdown 使用受控渲染和 HTML 白名单，首期也可先只显示纯文本；不直接注入作者 HTML。
- 设定名称、章节、正文、链接和总条目数量上限，在前后端同时提示，但以后端校验为准。
- 公开专题只能引用作者自己的站内文章。允许收录他人文章涉及署名、撤回和滥用处理，留作后续明确需求。

## 8. 验收标准

实施完成至少验证：

1. 从“步骤指南”创建租房心得专题，包含 4 个以上章节，以及 NOTE、POST、LINK 三类条目；调整顺序后刷新仍一致。
2. 从“阅读路线”创建动漫阅读专题，修改模板章节并成功保存、预览和发布。
3. 草稿不出现在专题广场，匿名直达不可读取；发布后出现在广场并可加入自选专题。
4. 账号 A 不能读取或修改账号 B 的草稿；旧 revision 保存返回 409，不覆盖新内容。
5. 非法 URL、超限章节/条目、类型字段不匹配均被后端拒绝；合法外链安全打开。
6. 现有专题迁移后仍公开可见，文章数量和现有显示顺序不变。
7. `/me/collections/new`、编辑页和公开详情支持直达、刷新、前进后退；1440×900 与 390×844 无横向溢出。
8. Vue 构建、H2 行为测试及隔离 PostgreSQL 17.11 的 V1–V6 迁移/行为测试通过；不得在主库造验收数据。

## 9. 实施顺序

1. **数据与兼容层**：V6、新实体/DTO、现有专题回填及只读兼容测试。
2. **草稿 API**：所有权、revision 并发控制、完整文档事务保存、发布/归档校验。
3. **专题工作台**：模板选择、章节和条目编辑、站内内容选择、自动保存与错误恢复。
4. **公开阅读页**：目录、编号路线、不同条目类型和旧专题兼容展示。
5. **回归与交接**：H2、隔离 PostgreSQL、双账号权限、浏览器桌面/移动验收，更新版本记录。

每一步都应可独立验证；不要在同一轮顺带加入协作编辑、推荐算法或外部 AI 服务。

## 10. 后续增强，不纳入第一期

- AI 根据主题、目标读者和素材生成可编辑大纲；生成结果只能进入草稿，不能自动发布。具体模型、费用、隐私和失败回退需另行确认。
- 读者进度、清单勾选和跨设备同步。
- 多人协作、评论定位到章节、版本历史和回滚。
- 链接元数据抓取、封面图片上传和第三方批量导入。
- 收录其他作者的站内内容，以及对应的署名、撤回和通知机制。
