# FINNS-REQ-014：专题创建与自定义页面需求规格说明书

版本：0.5｜更新日期：2026-10-09｜状态：待用户确认，尚未冻结。

本稿按“做什么 → 怎么使用 → 每项功能的要求 → 怎样确认完成”组织，供产品需求评审。0.2 是历史已评审基线；本稿汇总后续确认内容并调整表达，不能视为已经整体通过。

当前工作顺序：**确认需规并冻结 → 确定产品原型 → 概要设计 → 详细设计 → 开发 → 测试与验收。** 本阶段只整理和评审需求，已有原型保留作参考，不继续修改原型来反推需求。

## 1. 我们要做什么

让创作者把自己的经历、知识或资料，快速整理成一个可以阅读的专题页面。创作者可以先与 AI 沟通，再确认创建问卷，由 AI 整理出初稿，自己修改内容和页面，最后保存为私人草稿。

页面由一个个独立的内容模块组成。创作者可以增加、删除、移动和调整模块大小，也可以通过 HTML + CSS 导入自定义模块，例如时间轴。

首个案例是“大学生实习短租指南”。产品也应能创建看番路线、工具学习等专题，不将租房字段和章节固定为所有专题的结构。

## 2. 谁会使用

- **创作者**：整理资料、填写问卷、修改页面、创建自定义模块、保存草稿。
- **读者**：阅读创作者最终整理的内容；通过桌面和手机的阅读体验检查页面是否好用。
- **AI**：根据创作者确认的信息和提供的资料，帮助整理初稿；不能代替创作者确认事实。

普通创作者可以使用默认风格和已有模块完成创建。代码导入是可选的进阶入口，不要求每个人学习 HTML 或 CSS。

## 3. 这轮做到哪里

### 3.1 已确认的首轮方向

1. 与 AI 沟通后，打开专题创建问卷。
2. 问卷包含目标人群、用途和有具体说明的页面风格。
3. 作者确认需求后，由 AI 整理出可以继续修改的页面。
4. 内容模块支持编辑、增加、删除和调整阅读顺序。
5. 自由画布支持移动模块及调整大小，并考虑手机阅读。
6. 支持 HTML + CSS 自定义模块导入、检查、预览和再次编辑源码。
7. 页面保存为私人草稿，之后可以再次打开继续编辑。

### 3.2 继续保留、后续安排的方向

- 将结构、布局和样式保存为模板，再应用到其他专题。
- 增加更多官方模块，例如图片、清单、原生时间轴。
- 评估更简洁的模块语言、Mermaid 图表和受控组件扩展。
- 公开模板、模板分享等能力另行确定范围。

模板复用是整体产品方向；个人模板保存及共享是否进入首轮，仍需确认。既有专题发布能力继续保留，但本轮新增流程的终点是私人草稿。

### 3.3 本轮不包含

- 为租房、动画、学习工具分别开发一套专用页面。
- 自动搜集网络资料或保证生成内容已经核验。
- 运行用户 JavaScript、任意 Vue 文件或加载外部依赖。
- 完整还原任意网页，以及 PDF、Word、图片识别等复杂导入。
- 多人协作、模板交易等尚未讨论清楚的能力。

## 4. 用户使用流程

1. **说出想法**：说明想做什么专题、希望帮助哪些人。
2. **填写问卷**：确认主题、人群、用途、风格，补充资料和要求。
3. **核对摘要**：检查系统理解是否正确，修改后再确认。
4. **生成初稿**：AI 根据确认信息组织内容，标出缺失信息。
5. **修改页面**：编辑正文、调整模块、移动和缩放；按需导入自定义模块。
6. **检查预览**：查看桌面和手机效果，确认内容和阅读顺序。
7. **保存草稿**：保存当前成果，之后再次打开继续修改。

不需要自定义模块时，可以直接完成普通专题创建。无资料时怎样生成、问卷哪些字段必答，见第 8 节待确认事项。

## 5. 功能要求：逐项确认

本节写用户应当具备的能力。已确认方向见第 3 节；字段规则、具体选项和适配策略中的建议仍需审核。本节不表示正式功能已经实现。

### 5.1 与 AI 沟通并确认问卷（F11、F12）

- 创作者可以输入自己的专题想法，不要求先选择固定主题。
- AI 可以将对话中已经明确的信息填写到问卷中。
- 创作者可以查看、补充和修改预填答案；AI 推断不能直接算作作者确认。
- 目标人群和用途允许自定义文字，避免被少量标签限制。
- 页面风格必须说明呈现特点，让作者理解选择后的效果。
- 生成前展示需求摘要；作者可以返回修改，确认后再生成。

**核对结果**：摘要显示作者最后确认的答案，生成使用这份答案。

### 5.2 提供资料并生成页面初稿（F01、F06）

- 创作者可以提供已有文字资料，作为 AI 整理的依据。
- AI 根据主题、人群、用途、风格及补充要求组织内容。
- 生成结果由可以继续编辑的模块组成。
- 原始资料应保留供作者核对。
- 缺失、无法确定的信息要标出，供作者补充。
- AI 新增的建议应与已有资料区分，不冒充已经核验的事实。

**核对结果**：作者能看懂初稿结构、找到原始资料，并知道哪些内容还需要补充。

### 5.3 手动修改内容模块（F02、F04、F08）

- 可以修改模块标题和正文。
- 可以增加模块、删除模块，并调整阅读顺序。
- 可以在本轮支持的内容形式之间选择；具体形式清单待确认。
- 修改页面风格或布局时，应保留已有内容。
- 不使用模板或自定义样式，也有可阅读的默认页面。
- 同一套编辑方式适用于租房、看番路线、工具学习等不同专题。

**核对结果**：作者可以完成常见内容修改，不需要修改项目代码。

### 5.4 自由移动模块和调整大小（F03）

- 可以在内容画布内调整模块的横向、纵向位置。
- 可以调整模块宽度和高度。
- 模块位置与阅读顺序分别管理；移动位置不自动改变阅读顺序。
- 提供适合鼠标、触屏及键盘的操作途径。
- 手机阅读时内容应保持可读，不能仅将桌面页面整体缩小。
- 从手机预览切回桌面时，应保留原有桌面布局。

**核对结果**：模块可以摆放和缩放；保存、再次打开及切换设备预览后，内容和布局不丢失。

**待确认**：手机默认堆叠还是保留构图；重叠、层级、吸附、尺寸和高度规则。已有原型采用的数值不自动成为需求。

### 5.5 导入 HTML + CSS 自定义模块（F14、F15、F16）

- 可以填写模块名称，并粘贴 HTML + CSS 代码。
- 可以选择 UTF-8 HTML 文件导入。
- 提供时间轴示例，帮助作者理解代码模块的用途。
- 先检查代码并查看预览，作者确认后再添加到页面。
- 添加后，该模块可以移动、缩放、删除和保存。
- 可以重新打开源码继续修改；修改源码保留模块身份、阅读顺序和桌面布局。
- 源码修改后需要重新检查，不能用上一次检查结果应用新代码。
- 检查失败或作者取消操作时，原有模块保持不变。
- 自定义模块的样式只影响模块自身，不影响平台或其他模块。
- 首轮使用静态 HTML + CSS，不运行用户脚本，不加载外部依赖。

**核对结果**：作者能完成“导入 → 检查预览 → 添加 → 移动/缩放 → 修改源码 → 保存并重开”。

**适配责任**：平台负责模块容器和页面阅读顺序；模块内部通过作者 CSS 适配。固定宽度内容不会被系统自动改写，超出时如何显示需明确提示。

### 5.6 查看桌面和手机效果（F03、F08）

- 可以在保存前查看页面的阅读效果。
- 可以检查桌面和手机两种显示方式。
- 预览应体现当前内容、样式和布局。
- 预览中应能发现文字溢出、阅读顺序不合理等问题。
- 超出系统支持范围的样式要求应有说明，不能承诺任意效果。
- 手机适配方案在需规中确认，按钮位置、面板形式等在原型阶段确定。

**核对结果**：作者可以判断读者实际会看到什么，并返回继续修改。

### 5.7 保存私人草稿并继续编辑（F10、F13）

- 可以保存专题名称、内容、阅读顺序、布局和样式。
- 自定义模块同时保存原始源码及再次显示所需的信息。
- 可以再次打开已保存草稿，继续编辑。
- 保存的内容不能因移动、缩放或再次打开而被 AI 自动重写。
- 草稿仅作者本人可访问，生成和导入不自动公开。
- 应让作者区分已保存和未保存的修改。

**核对结果**：再次打开后，保存的内容和设置仍在；其他用户不能读取或修改私人草稿。

这里描述正式产品的保存要求。现有原型的浏览器演示存储不能作为正式账号隔离或服务端保存已经完成的证据。

### 5.8 处理失败和重新生成（F07、F09）

- AI 生成失败时，保留问卷、原始资料和已有编辑。
- 作者可以重试，或返回手动修改。
- 再次使用 AI 调整时，先查看结果，再决定是否接受。
- 接受新结果前，不直接覆盖作者已经编辑的内容。
- 重试不应无故产生重复作品。
- 代码导入错误应指出问题，便于修改后重试。

**核对结果**：一次失败、取消或重试，不导致已有成果丢失或被未经确认替换。

### 5.9 应用和复用模板（F05，具体轮次待确认）

- 模板可以提供模块结构、布局、样式和填写提示。
- 应用模板后，可以继续修改、删除和增加模块。
- 模板选择是可选操作，不影响从默认页面开始创建。
- “复用结构与样式”与“复制全部内容”应有明确区别。
- 从租房模板创建其他主题时，不强迫填写租期、房东等租房字段。
- 保存个人模板、导出和共享的范围分别确认。

**核对结果**：模板帮助快速起稿，也允许作者形成自己的页面，不把作品锁死在固定结构中。

## 6. 创建时填写什么

以下是便于确认的字段建议；“需要确认”不等于必须手写，可以接受系统推荐、再由作者确认。

| 信息 | 建议要求 | 示例或说明 |
| --- | --- | --- |
| 专题主题/名称 | 需要确认 | 大学生实习短租指南；工作名称可后续修改 |
| 目标人群 | 需要确认 | 初次外地实习的大学生；允许“不限定人群” |
| 主要用途 | 需要确认 | 避坑、看番路线、学习工具；允许自定义 |
| 页面风格 | 需要确认 | 可接受系统推荐，但应知道具体效果 |
| 希望读者完成什么 | 建议填写 | 了解看房前准备事项 |
| 已有资料 | 按创作方式提供 | 粘贴文字、TXT/Markdown；无资料规则待确认 |
| 要包含或避免什么 | 可选 | 保留来源、不改变某部分顺序 |
| 适用背景 | 按主题提示，可选 | 地区、时间、工具版本、读者基础 |

其他填写规则：

- 封面、模板、自定义颜色和代码模块均不是普通创建的必填项。
- HTML 模块需要名称和通过检查的非空代码；显示高度可由系统提供默认值。
- 作者归属、保存状态等内部信息由系统维护。
- 私人草稿允许内容未完成；公开发布要求不在本轮新增闭环中重新定义。

风格候选及说明：

- **清晰指南**：单栏阅读、明确章节层级、适中留白，突出行动步骤。
- **问题卡片**：按问题分组，突出标题和行动建议，便于查找。
- **路线时间线**：突出先后顺序，可用于观看路线或学习路径。
- **学习文档**：目录和标题清晰，装饰较少，适合反复查阅。

具体保留哪些风格仍需确认；风格与用途可以自由组合。

## 7. 用租房案例检查通用性

1. 输入“给初次外地实习的大学生做短租指南”。
2. 确认人群、避坑用途和页面风格，提供已有资料。
3. 检查 AI 是否整理出可修改的内容，并标出缺失信息。
4. 修改正文、增删模块、调整阅读顺序及页面布局。
5. 按需导入时间轴模块，检查桌面和手机效果。
6. 保存草稿，再次打开确认内容和布局。
7. 换成看番或工具学习资料，检查是否能沿用同一流程。

案例用于检查创建能力。租房建议本身仍需结合真实情境核验。

## 9. 怎样判断功能完成

以下为正式产品的拟定验收条件，便于逐项核对，不表示已经验收。

| 编号 | 要检查什么 | 应看到的结果 |
| --- | --- | --- |
| A01 | 用已有资料生成初稿 | 得到可编辑模块，原文可核对，缺失信息可识别 |
| A02 | 修改内容 | 编辑、增删及重排后，预览体现最新修改 |
| A03 | 保存并重开 | 内容和页面设置恢复，草稿归属不变 |
| A04 | 换一种主题 | 同一套创建方式适用，不要求填写租房专用字段 |
| A05 | 模板复用（若纳入本轮） | 结构、样式及正文复制范围符合作者选择 |
| A06 | 生成失败或重新整理 | 原资料和已有成果保留，接受前不覆盖，不无故重复建作品 |
| A07 | 使用默认值 | 不选封面、模板、自定义配色也能完成草稿 |
| A08 | 桌面和手机预览 | 阅读可用、主要操作可达，无非预期页面横向溢出 |
| A09 | 私人草稿与公开内容隔离 | 未发布草稿仅作者可见，不能修改他人内容 |
| A10 | 修改问卷 | 答案可修改、摘要一致；关闭再开是否保留按确认规则验收 |
| A11 | 按确认答案生成 | 人群、用途和风格在结果中可核对，旧结果不冒充新结果 |
| A12 | 自由定位和缩放 | 位置/尺寸保存，手机可读，回桌面保留构图及独立阅读顺序 |
| A13 | 导入代码模块 | 粘贴或文件导入、检查、添加、源码编辑、移动及保存可完成 |
| A14 | 错误、修改和取消导入 | 问题有提示；新代码需重检；取消不修改原模块 |
| A15 | 自定义模块再次打开 | 源码和显示设置恢复，编辑保留模块身份和布局，旧普通草稿兼容 |
| A16 | 自定义模块隔离与适配 | 不污染平台，不运行用户脚本或外部依赖，按确认的容器/内部适配规则显示 |

首轮实际验收集合随第 8 节范围确认后冻结。公开发布、模板共享等后续能力不得直接套用为首轮交付要求。

## 10. 需规怎样冻结

1. 用户按第 5 节逐项确认功能，再处理第 8 节影响首轮的未决事项。
2. 整理出无歧义的首轮范围和验收清单，提交冻结版本。
3. 用户明确确认后，记录冻结版本及日期；当前 0.5 仍为待确认稿。
4. 原型围绕冻结需规确定操作流程和页面表现，不自行增加或减少功能。

“冻结”表示后续工作有稳定依据。新的讨论、原型实现或 AI 建议都不自动改变已确认版本。
