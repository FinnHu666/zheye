评审开始日期：2026-10-11。修订：3，修订日期：2026-10-12（新增创作者自定义实体方向）。当前版本：0.6.0。状态：方向、自定义实体及首期私人/独立复制边界已确认，字段配置等具体规则待评审；仅需求评审，不实施、迁移、创建线上专题或发布。

## 1. 用户方向与需求拆分

用户明确的方向：

1. 首页显示**全站累计浏览量**，本轮不是逐篇文章/专题浏览量。
2. 接入管理员端，对指定用户的身份和访问内容进行限制；先做简单版。
3. 首期建立租房踩坑与方法专题；评价榜单支持城市/区筛选，由用户提交评分。
4. 榜单的评价实体类型由创作者定义，房源、租赁方、小区/公寓是租房预设示例，不是固定选项范围；作为可复用模块，与 HTML 导入模块同属专题区块体系，后台也须具备扩展能力，以后方便其他专题导入。
5. 导入评价模块时**复制模块配置，建立独立空榜单**，不共享来源评分。
6. 首期租房专题和榜单**先作为私人草稿验证**，本批次不新增公开发布或开放公众评分。
7. 本轮追加明确：创作者可以定义评价实体的选择范围，不应每增加一种实体都要求开发者改代码。自定义字段、筛选与量表的具体编辑能力是下文建议，尚未整体冻结。

## 3. REQ-015：首页全站累计浏览量

### 功能分点

1. 首页显示“累计浏览量”，统计开始时间可查看；加载/失败显示未知状态，真实零显示 0。
2. 统计全站符合口径的阅读访问，不将累计浏览量标为独立人数、注册人数或活跃人数。
3. 首期推荐统计公开阅读页面/内容，排除编辑工作台、私人预览、后台、API 轮询和静态资源；“全站”是否包括个人页面须在口径中明确，不能静默排除。
4. 推荐同一会话对同一阅读对象在短窗口内刷新不重复计数，窗口暂建议 30 分钟；正常访问其他对象分别累计。该口径是经过基础去重的浏览次数，不是严格 UV。
5. 文章当前在首页弹层打开，要明确打开文章算一个独立阅读对象；仅列表展示、预加载、刷新统计接口或无限翻页请求不算阅读。
6. 计数从正式启用开始，历史未知量不补造；计数重启后恢复，并发请求不会丢失更新。
7. 基础限速和重复上报保护；首期不承诺完全识别所有机器人，不以设备指纹搜集更多个人信息。

### 验收

- V01：首页值与服务端持久统计一致，重启后保留，起始时间明确。
- V02：约定阅读行为计数；编辑/后台/列表请求不误计，刷新去重与窗口边界一致。
- V03：并发、重复上报和失败重试不会重复或丢计；统计失败不阻断阅读。
- V04：无历史值时显示从启用开始的数据；无法读取时显示未知，不回落为虚假 0。

不在本轮顺带增加逐篇浏览量、热门排序、UV、访问明细报表或完整埋点平台。

## 4. REQ-016：简单管理员端与访问限制

### 推荐的最小规则（待确认）

1. 两个管理身份：普通用户、管理员；角色由服务端维护，注册表单不能选择管理员。
2. 对指定用户开启/关闭一个“受限内容访问资格”；页面/专题可标记公开或受限。普通公开内容保留既有访问规则，受限资源默认不开放。
3. 首期不做任意角色编辑器、付费会员、复杂授权表达式或逐个组件权限。若用户希望对多个页面分别授权，须明确这一项扩展，而不是偷偷把一个资格扩成全套权限平台。
4. 管理员页面列出并搜索/分页用户，修改资格，查看变更前后值与操作记录；涉及新增管理员需明确首个管理员的安全指定方式，并避免删除最后一个管理员。
5. 前端按权限显示导航、页面或无权限状态；服务端同时校验列表、详情及写操作。直接输入 URL 或调用 API 均不能越权。
6. 搜索结果、摘要、关联条目、列表总数、缓存及附件不能旁路暴露受限内容；撤销资格在后续请求生效，不要求用户先退出。
7. 登录/退出、个人资料和必要的恢复入口仍可操作；访问受限不自动等于封禁账号、删除数据或移交私人草稿。
8. 管理员不因角色自动取得其他用户完整 AI Key、私人本地工具或私人草稿读取权。

“界面可见”与“后端准许读取”必须同一规则。服务端逐请求校验、最小权限及默认拒绝受限资源参考 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)；上述最小资格模型是本项目建议，不是该指南指定的数据模型。

### 管理入口分工

- **访问管理**：用户资格及审计，是本项首期能力。
- **榜单审核**：对象、评分、投诉的审核动作属于 REQ-018，共用管理入口但独立权限检查与操作记录，不将用户资格和评分有效性混成一个开关。

### 验收

- P01：游客、普通用户不能打开管理功能或调用管理接口；不能修改自己资格。
- P02：允许/拒绝两组用户在导航、直达、列表/详情 API、关联内容和缓存上结果一致。
- P03：撤销权限后下一请求不返回受限正文，已有保存数据不被删除；保留登录/退出和个人资料入口。
- P04：管理写请求校验 CSRF、角色、目标对象及并发状态；审计包含操作者/目标/时间/前后值，不能泄漏秘密。

## 5. REQ-017：首期租房知识专题

### 推荐的内容组织

1. **读者与使用场景**：第一次租房、实习/短期居住者；大学生是已讨论案例，不自动排除其他人。
2. **租前准备**：预算、通勤、租期和必要条件，形成可填写清单。
3. **找房与辨识**：房源来源、信息核对和常见诱导方式，区分事实资料与作者经验。
4. **看房检查**：环境、设施、费用项目和记录办法，提供按步骤使用的检查清单。
5. **签约/入住/退租**：需要核对的问题、交接证据与复盘方法；地方规则和法律性表述应另查权威资料，不能凭模型生成当作已核实建议。
6. **城市经验与评价入口**：嵌入 REQ-018 模块；说明评分是用户经验、样本及更新时间，不能代替对具体房源的现场核验。

### 首期边界

- 准备可审阅的内容大纲、资料来源、更新时间和缺项，确认后建立本人的私人专题；本轮不发布生成的租房建议。
- 首期推荐试点一个城市，但用户要求的城市/区筛选能力保留；城市及资料由后续明确，不擅自选择或伪造各城评分。
- 先有实用知识内容和清单，榜单无评分时仍能阅读指南。
- 本轮已确认首期私人草稿验证，推荐沿用 BUILDER 区块/画布体系；不新增公开榜单、专题发布、分享链接或访客查看。现有传统编辑器也不自动获得新增模块。

### 验收

- R01：目录有明确使用顺序，可用检查清单；资料/经验/待补充标记可辨识。
- R02：城市规则附适用地区与更新时间；未知内容保留待补充，不伪造真实榜单。
- R03：本人私人稿可直达、保存刷新并在手机阅读；其他账号与未登录用户不能读取，公开列表不会出现该稿。

## 6. REQ-018：通用评价榜单模块

### 6.1 模块形态与对象

1. 专题“添加区块”中提供评价榜单模块，与文字、步骤、问答、HTML 等并列；具备编辑、预览、收藏/复用和画布/手机适配规则。
2. 创作者可新增、命名、调整顺序或停用自己的实体类型，例如“房源”“租赁方”“课程”“工具”；租房预设可作为起点，并能增改，不将这些业务类型写死在前后端枚举中。
3. 租房模板默认提供城市和区联动，区必须属于所选城市，支持全市；城市切换重置无效区。其他专题可关闭地域筛选，改用所属分类、适用人群等已定义字段，不强制所有实体具有城市/区。
4. 每个具体对象有稳定 ID、所属实体类型及必要辨识信息；地域在启用时填写。同名对象不能仅凭名称合并，重复对象核对后合并，评分关联可追溯。
5. 不同对象类型分别展示、评分和排名；不同量表的分数不直接混成一个总榜。页面可显示不同类型的分区榜，仍保留统一入口。
6. 首期按地区手动选择，不要求地图、自动定位、全国 POI 导入、第三方房产抓取或交易系统。

### 6.1.1 实体定义与具体对象分开

- **实体类型定义**：决定“评什么”，例如课程或房源，由创作者管理。
- **具体对象记录**：该类型下的实际条目，例如某门课程或某套房源，具有独立 ID。
- **评价记录**：某位有资格的用户对该对象的评分与经验，关联实际对象，不能直接给类型标签计分。

创作者可以自定义类型名称与候选选项，也可以添加具体对象；第一期建议由创作者维护对象目录，其他用户提报新对象及审核流程是否纳入仍需确认。跨榜单不默认共用对象目录或评分。

### 6.1.2 推荐的定义界面与配置边界（待评审）

1. 创建实体类型时填写名称、说明，并定义对象属性。公共基础属性保留稳定对象 ID 和名称；业务属性由作者增加。
2. 首期建议支持文字、数字、单选、多选及可选地域字段。作者可设置标签、必填、允许值/候选项、显示顺序及可筛选属性；字段类型种类与容量限制在详设确定。
3. 地域字段使用平台提供的城市/区关联能力；作者无需自己实现联动。普通选项字段可以自行维护候选值，例如“授课形式”或“适用平台”。
4. 筛选界面按配置生成，文字搜索、选择条件及数字范围使用平台内置能力；作者定义业务选择，不上传任意查询代码。
5. 量表按实体类型配置。评分维度及红黑榜规则继续在需求评审中确定，不因自定义名称就允许任意执行公式。
6. 后台保存类型/字段/选项定义及修订，按该榜单的定义验证具体对象和评分，校验数据类型、候选项、必填和归属；只在前端新增标签不算完成自定义。
7. 不同量表仍分别排名。若未来需跨类型总榜，须先定义可比的共用维度及规则，不能直接混排。

| 创作者定义的类型（示例） | 可定义的对象属性（示例） | 可启用的筛选（示例） |
| --- | --- | --- |
| 房源 | 城市、区、月租、户型 | 城市/区、价格范围、户型 |
| 租赁服务 | 服务区域、服务形式 | 地域、服务形式 |
| 课程 | 学科、授课形式、适用人群 | 学科、授课形式、人群 |
| 工具 | 用途、运行平台、收费方式 | 用途、平台、收费方式 |

这些只是预设示例，不是允许类型清单；添加新的业务类型应通过定义界面完成。新增平台尚不支持的字段类型、特殊计算或外部数据连接仍属独立开发范围，不能将“可扩展”解释为任意代码插件。

### 6.1.3 定义变化与历史数据（待评审）

建议使用稳定类型/字段/选项 ID，显示名称与标识分开。名称或顺序变化不改变已有关联；新增字段对旧对象显示缺项，不静默填入虚假值；使用中的类型/选项先停用，保留历史对象和评分。更改字段类型、评分维度或计算规则时提示影响，保留定义修订，明确旧记录如何显示及是否进入当前榜，不能用新规则无提示重解释旧评分。

### 6.2 用户评分与结果

1. 有提交资格的登录用户选择对象，提交分数、文字经验和发生时期；“上传打分”首期建议理解为提交表单。图片/合同附件是否需要上传另定，不默认为已包含文件服务。
2. 推荐 1–5 分。评分模板可按对象类型选择：房源侧重信息真实性/实际体验，租赁方侧重费用透明/服务履约等；最终维度及是否必须填写总体分待确认。
3. 同一用户对同一榜单对象在同一评价周期只有一条有效评价，可修改或撤回；修改不是重复加票，不得评价到不存在/不匹配的地区对象。
4. 用户提交后可看到待审/通过/驳回及原因；管理员不能不留痕地改变用户分数。
5. 推荐首期审核后公开和计入排名，支持投诉、下架、恢复及原因；编辑后的待审版本如何替换已有通过版本须在详设明确，不能重复计算两版。
6. 页面显示总体/维度分、有效评价数、分数分布和更新时间；未提交维度显示缺项，不当作 0 分；无有效评价显示“暂无评分”。
7. 红榜/黑榜作为明确条件下的评价排序视图，分数、样本门槛和时间窗公开；样本不足展示“样本不足，未入榜”，不能凭一个 5 分或 1 分确定长期榜位。
8. 首期门槛建议有效评价至少 5 条，红榜均分至少 4 分、黑榜不高于 2 分，并保留中间分段对象详情。以上数字仅为待评审参数，不是已确认规则；不强制凑满榜单条数。
9. 删除/撤回/下架/恢复会更新有效分数与榜位。榜单分页、稳定排序和重复提交保护；基本限速与异常重复审核，不宣称仅靠一个账号一票就能杜绝刷分。
10. 首期不得导入虚构评价。公开对象/经验不展示联系人电话、证件、合同原件或精确住户信息；特别是个人出租者，需明确可公开的辨识范围、纠错/申诉及证据可见性。产品审核不等于证实事实或作出违法认定。

首期展示只在本人私人稿。产品不开放公众投稿；多账号评分可在隔离测试中验证，但真实测试参与者的榜单访问/提交权限仍需明确，不能因登录、管理员身份或评分资格就打开他人的私人专题。若暂不提供参与者授权，界面先由本人验证，多账号归属/拒绝/统计用固定非敏感测试数据验证；不能据此声称已经完成多人线上使用验收。

### 6.3 后台扩展与模块复用

产品层面统一模块：**模块类型 + 配置 + 数据来源 + 权限 + 展示版本**。租房是第一个业务配置，其他专题可复用评价能力；首期不开发任意代码插件系统。

| 部分 | 职责 | 首期边界 |
| --- | --- | --- |
| 模块配置 | 标题、自定义实体类型/字段/候选项、可选地域、筛选、量表与展示选项 | 配置有界；平台字段类型可枚举，业务实体名称/选项由作者定义，不执行脚本/SQL |
| 评价对象与量表 | 稳定类型/字段/对象 ID，按定义校验属性及评分，保留修订 | 新业务类型通过配置界面创建，不需要改代码或新增一套数据库表；新基础能力另评审 |
| 评分与审核 | 用户提交、有效版本、审核/投诉、撤回及统计 | 后端权威数据，客户端不能传作者身份或直接写汇总分 |
| 渲染与交互 | 宽窄布局、加载/空/错误、列表/详情/打分 | 受控 Vue 功能组件，独立模块 ID；遵守宿主页面权限 |
| 导入/收藏/复制 | 保存可复用的模块配置，建立独立数据关系 | 本轮确认复制配置并新建空榜单，不迁移源评价或共享引用 |

用户已明确选择：**复制配置并创建独立空榜单**。复制内容包括自定义实体定义、字段及选项、筛选、量表和展示配置；插入时产生新模块/榜单及定义 ID，重建内部关联并归属当前作者，不复制具体对象记录、评分、评价、附件、审核记录或来源访问资格。配置收藏是保存时的快照，来源后续改定义不改变已收藏/导入的配置。

新榜单后续修改、添加对象和评分不影响来源；取消模块收藏不删除已插入榜单。首期对象目录和评分均按榜单独立，平台地域基础资料可以复用。共享对象目录或实时评分留待后续单独需求，不属于首期。

HTML 继续静态、隔离展示。功能模块通过平台组件调用受控接口；HTML 文件本身不因此获得任意 JS、个人 Key 或后端访问权限。后续导入完整模块包时，使用可校验的结构化配置；不能仅用 HTML 截图/文字包装冒充动态榜单。

未来如新增 BUILDER 公开发布，需单独确认页面配置快照与实时评分的关系，私人数据源不自动变公开。该发布设计不属于首期私人验证范围。

### 6.4 可观察验收

- B01：选择城市/区/对象类型后，显示对应对象；无数据、切换、刷新及分页正确，无跨地区或跨量表混排。
- B02：合法用户提交→待审→审核→统计/榜位出现；缺权限/未登录/重复/非法分/不存在对象提交均拒绝并保留输入。
- B03：修改/撤回/下架/恢复后只计算应计有效版本；并发与重试不多票，样本不足不入榜。
- B04：管理员审核有原因与审计；普通用户不能审核、改汇总分或读取私密证据。
- B05：模块导入/收藏/复用生成新模块与榜单身份，评分为零；来源配置/评分不变，目标作者和权限独立；篡改源 ID 不能读取他人私有数据。
- B06：作者无需改代码即可新增一种非租房实体，通过其字段/选项配置添加对象、筛选和评价；地域关闭后仍可使用，不硬编码租房业务类型。
- B07：桌面画布、手机阅读与本人私人预览可用，保存/刷新恢复；普通区块和 HTML 回归通过。公开发布不在本批次验收范围。
- B08：后台拒绝定义外的字段/候选值、错误类型及跨作者修改，不能只凭客户端表单检查；缺项不当成 0 分。
- B09：名称/顺序调整保留历史对象/评分关联；停用类型及评分规则变更有明确历史处理，不能丢失记录或无提示重算。
- B10：复制自定义实体配置到另一专题后，字段与选项可用、对象及评分为空；修改来源/收藏/副本互不影响。
