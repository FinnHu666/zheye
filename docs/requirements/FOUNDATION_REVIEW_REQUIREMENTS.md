## 3. 完整行为草案

本节及 REVIEW-P01–P04 已随修订3整项通过；**需求批准不作为业务开发授权**。

| 对象/动作 | 敏感检测通过 | 命中第1/2次 | 命中第3次及本轮后续命中 |
| --- | --- | --- | --- |
| 文章、评论首次发布 | 直接发布 | 本次不公开，提示修改并保留输入 | 提交不可变快照给另一位审批者；通过才发布 |
| 专题首次公开或受限发布 | 进入首次审批，通过才发布 | 拦截并提示修改 | 一个待审任务同时标明首次审批与敏感复审原因，不要求重复审批 |
| 已获首次审批专题更新 | 更新发布 | 修改稿不公开 | 敏感复审，通过才更新 |
| 旧已发布内容后续修改 | 通过后更新，不补造首次审批 | 修改稿不公开 | 敏感复审，通过才更新 |

1. **检测时机与覆盖**：私人工作稿可保存；对外发布、更新发布及评论提交时，由服务端对用户提交的可见文字执行检测，覆盖标题/摘要/正文、专题名称/简介及条目文字、评论正文。客户端预检只用于提示，不能替代服务端。导入及其他发布入口适用同一规则。
2. **命中与计数**：每次实际提交且命中计一次，显示本轮第几次及处理结果；重复请求不得重复计数。第1/2次不公开，不自动提交人工。第3次起仍命中则转人工；修改后检测通过可按对象正常路径继续，并结束本轮计数。手动批准发布也结束本轮；驳回不靠刷新页面清零。不同内容之间不累计，也不新增全账号惩罚机制。
3. **首次专题审批**：首次发布审批绑定快照；批准同时完成首次资格与该快照发布，不自动批准作者随后改动。以后更新只走敏感检测/升级复审。已批准专题由作者撤回后重新公开仍检测，不重复首次审批；独立下架限制必须另经恢复处理。
4. **更新与并发保护**：检测失败、命中或复审期间，旧有效发布版继续可见。作者更新工作稿不改变待审快照；明确重提后旧任务失效，旧结果不得覆盖较新内容。撤回、评论删除、作者停用、审核者失权/停用或内容下架后，过期审核不能重新公开；重复处理不重复发布。
5. **审批者与可见性**：仅正常且当前有独立审批权限的用户能查待审及处理。权限在请求及最终处理时核验；审批待审快照所需的读取权不转化为对外开放权，也不授予查看他人所有私人草稿、用户管理或全站审计的权限。本人可查看自己的状态及处理原因。最终发布仍遵守受限阅读权限。
6. **管理入口**：在现有管理端提供独立路由的内容审批页，可按类型、状态、作者、时间查询，查看快照与当前发布版，执行通过、驳回、下架及恢复复核。按独立内容权限处理作品，不套用用户管理的“站长/管理员/成员”账号管理层级；不能自审或自行批准恢复本人作品。
7. **原因与记录**：驳回、下架、恢复须填写原因；普通批准可附说明。操作者、对象、提交版本、时间、原因、触发类型（首次/敏感）及结果可追溯；普通读者不能查询待审正文、敏感命中详情或管理原因。审核者看相关处理历史不自动获得既有全站 `admin.audit` 权限。
8. **账号状态**：沿用 [F07 UA-R03/04/06](FOUNDATION_USER_ADMIN_REQUIREMENTS.md)及[现有契约](../iterations/0.7.0/CONTRACT_USER_ADMIN.md)：停用不自动隐藏已发布作品。未处理提交在作者停用后失效，账号恢复后需本人重提；账号恢复不自动恢复被下架内容。
9. **历史与下架**：保留旧内容的原可见范围、ID和来源，不倒填审批记录。人工下架是独立限制，作者保存、通过敏感检测或获普通更新审批不能解除。恢复由另一位有审批权限者复核特定快照并填写原因；恢复时重新检测，命中则合并敏感复审，不绕过原处置。
10. **异常与页面**：加载、空结果、失败、取消、状态过期、重复操作、无可用审批者均有明确状态；失败保留非敏感输入及当前发布版。支持桌面/390px/768px、直达刷新及前进后退。检测异常时不发布新内容，私人保存可继续。

## 9. 修订5：检测规范化与多模式匹配（2026-10-20，REVIEW-D17）

在修订3/4 不变的前提下，把 REVIEW-D08 留给设计的“具体匹配、规范化”定义为下列可观察要求，随用户选择 B2 冻结；验收未执行。

- **REVIEW-P07 检测规范化与匹配**：
  1. **规范化**：提交文字与规则词语使用同一套规范化——全半角统一、转小写、去掉全部空白，**以及零宽字符、控制字符、标点和符号**。因此 `b.a.d.w.o.r.d`、`b a d`、`ＢＡＤ` 与规则 `bad` 等价。规范化后为空的规则词语（只含标点/空白）拒绝保存。
  2. **匹配方式（每条规则一项）**：`子串`（默认，保持修订3行为）或`整词`。整词只约束以英文字母/数字开头或结尾的一端：该端相邻处必须是原文中的分隔（空白、标点、零宽字符或文本边界）；中文端不受约束。整词模式不能解决中文短词误伤（如规则“习”命中“学习”）——此类需使用更长的词或接受人工复审，不在本期范围。
  3. **算法**：对全部启用规则建立多模式匹配自动机（DFA/Aho-Corasick），文本只扫描一遍，一次得到全部命中词（去重、保持规则顺序）。结果与逐条规则子串匹配**逐位一致**（仅速度不同）；不引入第三方依赖。
  4. **不在范围**：拼音、同义词、谐音、繁简转换、错别字、图片/附件、外部审查服务和 AI 语义检测。
  5. **样例**：提供可审阅的[示例词库与误报样例](../iterations/0.7.0/SENSITIVE_LEXICON_SAMPLES.md)，只含中性示例；不写入生产迁移，生产规则由站长自行配置；启用规则为 0 时仍阻止发布（沿用 REVIEW-P03）。

## 10. 修订6（已确认；2026-10-20，REVIEW-D18/D19/D20）

### 10.1 本任务项的边界

FINNS-17 只负责**审核环节**：敏感检测、人工送审与复核、下架恢复，以及把这些环节的**流转过程展示出来**。文章/话题的创建、草稿、手动保存、发布、“我的内容”状态（FINNS-18）和专题的创建、送审、撤回、复制（FINNS-19）不在本项内，各自 G1 仍待确认；本项为它们预留可扩展的阶段展示（P10）。

### 10.2 REVIEW-P08 敏感三级与统一流程（文章、评论、专题一致）

规则由站长维护，每条规则标注等级：`低`、`中`、`高`（默认 `中`）；系统不内置任何政治类词汇。一次提交命中多条规则时，**取最高等级**。

| 命中的最高等级 | 处理 | 作者看到 |
| --- | --- | --- |
| 无命中 | 直接发布 | 已发布 |
| **低** | **不拦截，直接发布**，并在审核记录里留痕（等级、命中词），供站长事后查看 | 已发布 |
| **中** | **直接送审**：内容不公开，进入待人工审核；审批人通过才发布，驳回需原因 | 待审核；驳回时看到原因 |
| **高** | **自动不通过**，内容不公开，**同时生成人工复核任务**；审批人可“维持不通过”或“判定误判并放行发布”（均须原因）；作者改稿重提使旧任务失效 | 未通过：包含不允许发布的内容；**不展示具体命中词** |

通用规则：
1. **专题与文章流程一致**：专题首次公开发布**不再**无条件人工审批，无命中即发布；私人草稿仍可自由创建和编辑。专题的“首次审批”触发类型取消。
2. 取消“前2次拦截、第3次人工”的计数：因此不再需要命中次数、拦截状态及 `draftKey` 计数。
3. 禁止自审、独立审批权限、快照审批、旧发布版保护、下架优先、原因必填、账号停用使待审失效等已确认规则不变。
4. 检测不可用或启用规则为 0 仍阻止发布（P03）。
5. 同步毫秒级检测保持；真异步与后台队列推迟到 FINNS-18/19 评审。

## 10.8 R3原型反馈带来的调整（2026-10-20，REVIEW-D21；随R3由REVIEW-D22确认）

1. **分页**：规则列表和审批队列显示页码并支持跳转，即使只有一页也显示总数与页码；不再只有“上一页/下一页”。
2. **流转过程**：审批详情把“流转过程”放到独立 tab（`内容与处理` / `流转过程`），可用地址直达；作者侧时间线不变。
3. **低敏感记录**：仍为“放行并留痕”，不是单纯放行：站长/审批人可**查看内容**（进入既有发布内容页）、**标记已阅/取消**、确有问题时**下架**（沿用既有下架流程，须原因）、或**调整该词规则等级**（只影响之后的提交）。
4. **词库导入（取代 §10.4 中“导入即停用、默认中级、逐批启用”）**：按标签批量导入；每个标签自动给出建议等级（演示映射：政治→高，诈骗/引流→中，广告→低），可调整，并可选择导入后**启用**或**停用**；疑似误报词（单字、常见地名人名等）**默认不导入**，需显式勾选；规则列表支持**按标签批量启用/停用**；导入弹窗内的样例检索**只读（仅查询），不提供增删改**；规则本身的增删改查仍在规则列表。标签与等级的真实映射待有真实词库后再确认，原型映射仅为演示。
