# F05 基础个人资料：查看与编辑分开

日期：2026-10-17（Asia/Singapore）。修订：2。内部需求：FINNS-REQ-020/PERSONAL。产品目标版本：0.7.0。原FND-P08草稿修订2由本轮V070-P12替代；只变更版本归属，PROFILE-01–07行为不变。

## 已明确的需求

用户指出：当前进入个人资料页面即可直接输入修改，只是在修改后多一个保存按钮；查看和修改应当分开页面，需要重新调整这一交互。

- 默认进入**只读的个人资料查看页**，昵称、简介等采用文本展示，不直接提供可编辑输入框或“保存”操作。
- 点击明确的“修改资料”入口后，进入**独立编辑页**；查看和编辑有独立路由，能直达、刷新和使用浏览器前进后退。
- 编辑是用户主动进入的行为，不采用查看页内直接输入、改完再出现保存按钮的现有方式。
- 这是 F05 的基础资料范围，与 F01 的账号安全维护一起优先评审；公开作者主页、我的作品和审核状态等部分随后按各自依赖推进。

上述交互要求已明确；下方字段、路径与异常行为为落实草案，具体页面仍需原型确认，尚未开发。

## 页面与行为草案

| 页面/动作 | 建议行为 |
| --- | --- |
| 查看页 | 沿用 `/me` 作为本人资料查看入口，展示现有昵称、简介及本人可见信息，提供“修改资料”按钮；保留个人中心导航 |
| 编辑页 | 建议 `/me/profile/edit`，仅在这里编辑昵称和简介，显示“保存修改”“取消”；页面布局待原型确认 |
| 可编辑字段 | 沿用已有昵称、简介及现有校验；邮箱当前只能查看，不顺带加入邮箱变更、头像上传或角色修改 |
| 保存成功 | 以服务端成功结果为准，返回查看页并显示更新后的资料，给出成功提示 |
| 保存失败 | 留在编辑页，说明错误并保留已输入内容，不冒充保存成功或跳回查看页 |
| 取消/离开 | 未修改时直接返回；有未保存修改时提示确认是否放弃，确认后返回查看页，不提交保存请求 |
| 登录与归属 | 两页均是本人私人区域；未登录按既有登录保护处理，接口从服务端会话确定用户，不能用可篡改的 ID 修改他人资料 |

密码维护仍由 F01 负责；账号停用、角色和权限由 F07 负责。本需求只调整本人资料的查看/编辑职责，不把私人资料暴露到公开作者主页。
