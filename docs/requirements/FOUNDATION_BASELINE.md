### F01 / FINNS-REQ-020/ACCOUNT：账号与身份维护

现有：注册、登录、退出及服务端会话。依据：`src/main/java/com/aitome/user/AuthController.java`、`frontend/src/App.vue`。

范围草案：
- 沿用邮箱登录、昵称和现有密码长度规则；登录失效时给出明确提示并保护未保存内容。
- 本人修改密码需核对旧密码、确认新密码；错误时不改变原凭据。不向管理员展示旧密码。
- 已确认账号恢复采用邮件自助，通过已验证邮箱接收一次性重置链接；主动改密保留当前设备、其他退出，邮件重置后全部退出并正常登录。邮箱验证/旧账号过渡、链接及发送细则待评审，见 [F01当前账号需规](FOUNDATION_ACCOUNT_REQUIREMENTS.md)。
- 已确认主动改密保留当前设备、退出其他设备；邮件重置后全部退出并正常登录。当前尚未实现或验证。

最低验收：正常注册/登录/退出；重复邮箱和错误密码；登录失效保护；旧密码错误不改密；恢复流程不能获取他人账号。邮件自助方向已定；会话、验证过渡与链接等细节未冻结，本项G1仍pending。

### F02 / FINNS-REQ-020/CONTENT：普通文章与话题的创作生命周期

现有：普通内容创建、列表、详情；尚无本人文章草稿、修改、撤回及审核闭环。依据：`ContentController.java`、`ComposerForm.vue`、`MyPostsPage.vue`。文章/话题共用现有内容模型，建议一起适配；是否仅先覆盖文章在分项评审确认。

范围草案：
- 新建及编辑先形成本人工作稿，显示保存状态，支持预览。发布前校验标题、摘要及正文；草稿和发布校验分开。
- 正文 Markdown 预览与阅读一致，包含标题、列表、引用、代码和链接；不执行原始 HTML，不增加外部图片加载或文件上传。
- 工作稿保存不会直接覆盖发布版；提交审核绑定不可被后续修改替换的内容快照。
- 审核中可继续修改工作稿；要重新提交时明确替换待审版本。旧审核结果不得批准新版本内容。
- 初次审核通过后才有发布版；更新审核驳回时旧发布版继续有效。作者可撤回，保留原稿，重新公开须再经过审核。
- 首期不做永久删除、任意历史版本回滚或多人协同编辑。撤回或下架的内容不再提供点赞、评论或新增收录入口。

最低验收：草稿保存刷新恢复；预览与阅读一致；待审正文不泄露；改稿不能替换审稿快照；驳回可重提；撤回后列表、检索、详情、公开主页和专题引用均不泄露原文；非作者不能改稿；版本冲突和保存失败保留输入。

### F03 / FINNS-REQ-020/COLLECTION：传统专题接入审核

现有：本人工作稿、导入、预览、发布快照、受限专题、归档及复制。依据：`CollectionWorkspaceController.java`、`CollectionPublicationService.java`、`CollectionEditorPage.vue`。复用这些能力，不重写专题编辑器。

范围草案：
- 将“直接发布/更新发布”改为提交审核，审核通过后生成对应公开或受限发布快照；工作稿与发布版继续隔离。
- 权限、受限可见范围及作品审核必须同时满足；有阅读权限不能跳过审核。
- 站内引用作品撤回/下架时，公开专题卡片显示原文不可用，不继续暴露原文标题、摘要或正文；作者自己填写的注释与系统引用信息分开处理。
- AI BUILDER 工作稿继续私人保存，不自动接入公开发布。
- 历史已发布专题如何过渡为待核验基线见 §5；不自动倒填真实审核记录。

最低验收：原有导入/编辑/私人预览兼容；待审不可公开；审核拒绝不影响旧发布快照；受限内容无法经搜索/引用越权读取；撤回引用与审核竞态不泄露内容；AI 私人稿仍不进入公开目录。

### F04 / FINNS-REQ-020/DISCOVERY：浏览、检索与阅读

现有：列表分页、按类型浏览、详情与专题目录；没有关键词搜索。页头放大镜当前返回首页。依据：`DiscoverPage.vue`、`CollectionsPage.vue`、`App.vue`、`ContentController.java`。

范围草案：
- 检索文章标题/摘要及专题名称/简介；区分结果类型，保留搜索词，支持分页、清空条件、空结果和失败重试。
- 首期不搜索正文、专题章节/条目，不做推荐、热度算法或独立搜索服务。
- 检索只基于审核通过且仍有效的发布版，先按权限过滤再计算数量和分页；工作稿、待审及被撤回/下架内容不进入结果。
- 已有详情直达、浏览器前进后退和移动端阅读需要核验，保留已可用入口，不因做搜索顺带重构全部路由。

最低验收：标题/摘要命中、跨类型结果、分页稳定；读者甲不能通过摘要/总数看见无权作品；作者改稿未通过审核时仍搜索旧发布版；网络失败可重试；手机可完成搜索到阅读的路径。

### F05 / FINNS-REQ-020/PERSONAL：私人个人中心与公开作者主页

现有：昵称/简介、我的内容、本人专题、自选专题、私人 AI 配置入口；无独立公开作者主页。依据：`PersonalPage.vue`、`PersonalNav.vue`、`MyPostsPage.vue`、`PersonalController.java`、`main.js`。

范围草案：
- 私人中心提供本人资料、账号设置、文章/专题管理、草稿/待审/驳回/已发布/已撤回入口及文章收藏。
- 本人可看到提交版本、审核状态和驳回原因；无需依赖单独通知中心才知道结果。
- 公开主页首期展示昵称、简介和访问者有权查看的已发布作品，分页浏览；没有作品时显示空态。
- 不展示邮箱、角色管理资料、私人草稿、审核中内容、账号设置、AI Key/配置或本地工具。
- 原有本人专题、自选专题和私人 AI 功能入口保持；公开作者页不等于开放这些数据。

最低验收：本人状态筛选能定位作品及审核结果；公开主页不泄露私人信息；甲访问乙的私人中心被拒；受限作品随访问者权限过滤；已有个人入口兼容，移动端可完成管理与浏览。

### F06 / FINNS-REQ-020/INTERACTION：文章收藏、点赞与审核评论

现有：点赞直接增加计数，评论可直接发布；已有自选专题不能当成文章收藏。依据：`ContentController.java`、`DiscoverPage.vue`、`SelectedCollectionsPage.vue`。

范围草案：
- 已登录且有互动权限的用户可收藏/取消收藏文章，在私人中心查看；重复提交不得重复收藏。
- 点赞以用户和文章关系记录，可取消；重复点击/重试不额外计数，展示当前用户是否已赞。
- 评论先进入待审核，仅本人和有审核权限者可见；通过后才计入公开评论列表与数量。
- 首期单层文字评论，不做评论图片、楼中楼、私信或评论编辑。本人可删除待审或已发布的评论，审核与删除并发不得使其重新公开；记录必要管理历史，不向公众展示已删正文。
- 收藏不授予额外阅读权，作品撤回/下架/权限改变后不可通过收藏继续读取原文。

最低验收：收藏/点赞幂等、取消后计数正确；待审评论不泄露正文或数量；驳回本人可见理由；删除与审核并发正确；被撤回作品不能继续评论，收藏不能绕过权限。

### F07 / FINNS-REQ-020/USER_ADMIN：账号状态与既有用户管理衔接

现有：用户搜索/筛选/分页、角色分配、角色定义与权限编辑、管理者保护及操作记录，已作为 FINNS-11 发布。依据：`AccessAdminController.java`、`AccessAdminService.java`、`Permission.java`、`docs/RELEASE_0.7.0.md`。不重复开发或重开 FINNS-11。

范围草案：
- 复用现有用户/角色/权限页面，补充正常/停用与恢复、理由及操作记录；停用不是删除用户，也不通过“受限成员”角色冒充账号停用。
- 建议停用后禁止登录，已有会话下一次受保护请求失效；退出仍可执行，账号恢复不自动解除停用。
- 至少保留一名正常且有必要管理权限的用户，避免通过停用绕过已有最后管理者保护。
- 停用与作品下架分开：是否同步隐藏其已发布作品为待评审项，不静默删除作品或评分数据。

最低验收：复用原角色变更/查询；停用和恢复实时生效；旧会话不可继续写入；越权管理拒绝；不能停用最后管理者；操作记录包含对象、原因及结果，不包含凭据。

### F08 / FINNS-REQ-020/REVIEW：统一作品与评论审核管理

现有：后台用户/角色操作记录；没有作品、评论的待审队列。范围草案：
- 后台按对象类型、状态、作者和提交时间查询，读取提交快照及当前发布版本；通过/驳回必须针对所查看的版本。
- 文章、传统专题和评论全部通过审核后才公开；角色中的发布或管理权限不代表免审核。
- 驳回和下架必须有原因；审核人、时间、目标版本和处理结果可追溯。重复操作或过期审核有明确结果，不重复发布。
- 作者撤回、删除评论、账号停用或其他管理动作使提交失效时，旧审核不能将其重新公开。
- 下架与作者撤回区分；重新公开不能单靠保存绕过审核。具体恢复入口及是否要求重新审核在分项评审确认。
- 审核权限默认授予谁、是否允许审核本人作品、是否支持专门审核员角色，列为待评审；不凭本轮文档自行增加角色。

最低验收：三类对象通过前均不可公开；驳回与重提可追踪；作者不能冒充审核者；只批准提交快照；过期/重复审核、撤回/删除与审核并发正确；下架后全读取链路不可绕过。

## 4. 如何搭配 Plane 逐步完成

1. **先登记总项**：FND-P01 已获确认并创建、回读为 FINNS-14“FINNS｜多人社区基础能力完善（未分版）”，以本基线为范围索引，不挂 Cycle/Release。
2. **逐组评审细节**：先 F01/F07 的身份与管理边界，再 F08 审核规则；随后 F02/F03 创作发布、F04/F05 读者与个人空间、F06 互动。每组解决自己的待决事项，不反复推翻已确认的先审后发等原则。
3. **再拆分项工作项**：一个工作项对应可验收结果；八个稳定后缀作为内部映射，具体卡片在分项评审时逐项确认创建/更新，可归属总项。不按 G0–G9 机械创建十张阶段卡。
4. **已定版本**：F01–F08目标均为0.7.0，按依赖组织实施批次；AI增强和每日名言继续待定，评价/租房仍暂缓。
5. **同步→原型→设计→实施→验证**：每个分项先满足 G1 与 Plane 检查点，再制作原型并确认具体范围，之后完成概设/详设及接口/验收映射，获授权后实施。管理状态变更单独确认，不能因登记完成就标 Done。
