## 1. 用户原意与目标

用户希望以租房专题为案例，形成一套自定义程度较高、其他人也能快速使用的专题创建方式。当前重点是弄懂如何快速导入专题、模板如何操作、哪些内容必要及哪些可选，不优先实现租房的个别业务板块。

产品目标：让不懂页面代码的创作者，将现有资料快速组织成可编辑的专题页面；既有可直接使用的默认结果，也能按自己的意图修改内容、结构、布局和样式，并复用合适的模板。

首个验证案例：面向中国大陆城市实习、租期约 1—6 个月、租房经验较少的大学生，组织一份租房专题。案例用于验证通用创建能力，不把租房专用字段固化为所有专题的必填字段。

目标用户以专题创作者为主；读者的阅读体验用于检验生成结果是否可用。首版不以整理租房知识本身作为主要交付目标。

2026-10-08 补充：用户要求快速迭代，先跑通整体流程。第一步是在与 AI 沟通后弹出专题创建问卷，通过目标人群、用途和有具体说明的页面风格等问题准确表达创作意图。高自定义搭建器仍是整体方向，其全部能力不自动成为第一次迭代的交付范围。

## 4. 基本概念与模板原则

| 概念 | 定义 |
| --- | --- |
| 原始资料 | 作者导入的文字或文件，是组织内容的输入。 |
| 创建问卷 | 将 AI 对话中的创作意图整理为作者可以选择、补充和确认的需求输入。 |
| 内容区块 | 页面中可独立编辑、移动及配置的内容单元。具体类型待首版范围评审。 |
| 页面布局 | 区块的顺序、分组、分栏与尺寸安排。 |
| 页面样式 | 区块或页面的主题、颜色、字号及间距等呈现设置。具体开放项待评审。 |
| 模板 | 可复用的区块结构、布局、样式和填写提示，可包含明确标注的示例内容。 |
| 专题 | 结合作者实际内容和页面配置形成的作品，保留私人草稿与公开发布的区别。 |

建议原则（待确认）：

- 模板提供起点，使用后可以删除、增加、改名、重排和调整样式。
- 模板选择可选；无模板时使用默认布局，也能完成创建。
- 内容、布局和样式分别调整，改外观时保留正文。
- AI 生成结果采用与手工编辑相同的区块能力，生成后仍可继续编辑。
- 模板复用区分“复用结构与样式”和“复制全部作品”，避免不经选择复制原作者正文。
- 原始资料格式与模板配置是两个概念，普通作者无需手写配置文件。

## 5. 快速迭代与用户操作流程

### 5.1 第一步：AI 沟通后弹出专题创建问卷

已确认交互方向：作者先与 AI 沟通想创建的专题，弹出问卷供作者准确表达目标人群、用途和期望页面风格。桌面弹窗与手机的具体呈现由原型确认。

建议操作：AI 从当前创作对话提取已有信息预填问卷，作者修改或补齐；确认后生成一份可见的创作需求摘要。再次打开时保留答案，作者可以返回修改。对话推断的答案不算作者已确认，不从无关个人信息推断目标人群。

下表是问卷字段建议，字段必答规则及具体选项仍待评审。首屏集中展示主题、人群、用途、风格；其他内容按需展开。

| 问题 | 建议操作形式 | 示例 | 建议必要性 |
| --- | --- | --- | --- |
| 想创建什么专题？ | 简短文字，支持对话预填和修改 | 大学生实习短租指南 | 需要确认；标题可以先是工作名称 |
| 主要给谁看？ | 人群建议＋可编辑说明 | 初次外地实习的大学生；刚接触某工具的新手 | 需要确认，可明确选择不限定人群 |
| 主要用途是什么？ | 选择一个主要用途，允许补充其他目的或自定义 | 避坑解决问题、看番路线、学习某项工具、资源整理、其他 | 需要确认；不用填写技术分类 |
| 希望读者看完能做什么？ | 一句成果说明，可由 AI 建议 | 知道看房前需要准备什么；能完成工具的第一次使用 | 建议填写，可先采用建议再修改 |
| 页面希望是什么风格？ | 带具体说明的风格卡片，支持自定义描述 | 清晰指南、问题卡片、路线时间线、学习文档 | 需要确认，也可选择系统推荐 |
| 有哪些现成资料？ | 粘贴或上传，与已导入资料关联 | 笔记、文章、TXT/Markdown | 生成实际内容时使用；填写问卷阶段可稍后补充 |
| 要包含或避免什么？ | 可选说明 | 保留来源；不改变原文顺序；暂不需要清单 | 可选 |
| 适用背景是什么？ | 可选背景说明 | 地区、时间、工具版本、读者已有基础 | 相关主题提示补充，不对所有专题强制 |

用途描述“帮助读者做什么”，风格描述“怎样呈现”，两者可以自由组合。人群和用途选择须允许补充文字，不能只提供几个固定标签。问卷信息应共同影响后续组织与呈现，不能只被保存为无作用的字段。

### 5.2 页面风格选项怎样说明

以下为首轮原型的候选示例，并非已确认全部实现。每个选项要说明布局、信息密度、视觉倾向及内容组织；原型中提供可查看的示意，避免只使用“简约、好看”等抽象词。

| 风格候选 | 具体说明示例 |
| --- | --- |
| 清晰指南 | 浅色背景、明显章节层级、适中留白，以单栏阅读和步骤说明为主，重点行动有突出提示。 |
| 问题卡片 | 按问题分组，用卡片区分不同主题，突出问题标题和行动建议，便于快速查找。 |
| 路线时间线 | 以编号和前后顺序展示节点，突出建议次序与分支提示，可用于看番路线或学习路径。 |
| 学习文档 | 以目录、标题层级、说明和示例组织内容，便于反复查阅，装饰较少。 |

作者可补充“偏暖色、信息紧凑、突出顺序”等文字偏好。首版需明确可以兑现的样式范围；超出范围的描述应提示，不能承诺任意页面设计。主题用途与风格不做一一绑定，租房也可以用文档或卡片形式。

### 5.3 第一次迭代的已确认闭环

AI 沟通 → 创建问卷 → 作者确认需求摘要 → AI 根据资料生成 → 可编辑预览 → 保存私人草稿。

首轮优先验证问卷是否准确、生成结果是否体现答案、修改是否保留、草稿能否再次打开。资料缺失时先标出待补充内容；是否允许仅凭主题生成空结构而不生成正文，列入待决事项。

建议先采用少量区块、布局与风格选项来跑通闭环；模板保存与共享、复杂分栏、完整样式编辑和交互区块分后续迭代评审。没有被移除的整体能力方向，不等于首轮全部实现。

### 5.4 手动创建与后续模板复用

作者也能从默认空白页面、已有模板或本人专题开始，不依赖 AI 才能编辑。选择模板后修改内容与页面配置；保存模板的具体范围、共享方式待确认。

上述是待评审的操作流程，不是已完成页面设计。拖动不是唯一操作方式；应提供适合手机和键盘的等效调整操作。

### 5.5 自由画布与简洁区块语言（2026-10-09 新增）

用户明确选择“自由画布，可以任意定位和调整大小”，不限于上下排序；要求考虑适配，并希望后期通过方便的专用语言创建区块，例如时间轴。首版箭头排序不再代表完整编辑方向。

方向已确认：模块可手动定位和缩放；代码创建与画布编辑围绕同一份区块记录。手机按独立阅读顺序堆叠、保留桌面构图是当前原型规则。HTML + CSS 作为本轮自定义入口，原生组件及后续图表能力的分工见 [区块设计说明](TOPIC_BLOCK_LANGUAGE_DESIGN.md)。具体原型体验和正式业务范围仍需评审。

### 5.6 HTML + CSS 自定义模块（2026-10-09 确认）

操作闭环：打开“导入 HTML 模块” → 填模块名称 → 粘贴代码或选择 UTF-8 `.html/.htm` 文件 → 检查并预览 → 确认添加 → 在画布移动/缩放 → 编辑源码 → 保存私人草稿并再次打开。提供可直接体验的时间轴示例，作者无需先学习新指令语法。

- 必需：模块名称、非空且通过支持范围检查的源码；系统提供默认显示高度。可选：文件导入、自定义 CSS、响应式规则、位置与尺寸调整。代码导入不成为普通专题创建的必填步骤。
- 代码通过检查后才能应用；源码改变使旧检查失效，旧预览明确标为上一次结果。错误或取消不改现有模块。编辑源码保留模块 ID、阅读顺序及桌面布局。
- 支持静态 HTML 片段、`<style>`/行内 CSS、原生 `details` 折叠；首轮不支持脚本、事件属性、Vue 标签、表单、SVG、外部资源/链接和嵌入。未知标签或属性提示后拒绝应用，不冒充已经完整支持任意网页。
- 原型限制：单块最多 60,000 个 JavaScript 字符长度单位，UTF-8 文件最多 128 KiB；嵌套最多 40 层、节点最多 2,000 个、最多 20 个 HTML 模块。流式/手机显示高度 120—1200px，画布尺寸沿用自由画布规则；超出内容在模块内滚动。
- 平台只保证模块容器的宽度适配和手机阅读顺序；代码内部通过作者 CSS 实现响应式布局。原型不自动修复固定宽度内容，不提供自动测量高度或内部节点拖拽。
- 保存原始源码、渲染规则版本、显示高度及布局。相同输入在相同版本规则下产生相同渲染文档；自然语言再次生成、不同浏览器字体和视口不承诺像素一致。规则升级必须定义兼容或迁移，不悄悄覆盖原文。

区块候选：文字、图片、链接、步骤、问答、清单。候选清单不等于首版全部必做；应根据租房案例和另一个不同主题确认最小组合。图片上传、交互清单等有独立数据与交互需求，不能仅凭区块名称视为已确定范围。

## 7. 必要信息与可选信息

以下为建议的填写规则，需在需求评审中确认。区分“系统必需能力”和“用户必填信息”，尽量由系统提供默认值。

| 信息或操作 | 创建与保存草稿 | 公开发布 |

系统自动维护作者归属、保存状态及其他内部信息，不让用户为了创建专题填写技术字段。

## 8. 租房案例如何验证通用能力

输入：作者已有的大学生实习短租资料，以及确认后的创建问卷。例如：主题“实习短租指南”、人群“初次外地实习的大学生”、用途“避坑解决问题”、成果“了解租房准备及行动顺序”、风格“清晰指南”。租房规则、地区差异和资料核验另行开展，本说明书不提供已核验的租房建议。

候选生成结果：专题介绍、阶段组织、问题解答和行动清单。作者可以删去清单、改为问答，调整顺序或分栏；这种修改不应依赖修改业务代码。

保存模板时，租房正文可转为填写提示或示例。再用另一份不同主题的资料，例如学习路线，检查能否复用或调整模板而无需填写租期、房东等租房字段。这里验证的是通用性，不新增学习领域专属业务。

案例生成结果经作者审阅后才能作为正式内容；演示资料和真实内容应明确区分。

## 9. 拟定验收条件

以下是验收要求，不表示正式业务已验收。独立原型已验证的场景及未执行项见 [产品原型说明](TOPIC_BUILDER_PROTOTYPE.md)。

| 编号 | 场景 | 可观察结果 |
| --- | --- | --- |
| A01 | 作者提供租房资料并发起 AI 整理 | 得到可编辑的区块与布局初稿，可查看资料并识别待补充信息。 |
| A02 | 修改生成结果 | 修改正文、添加/删除区块、调整顺序及首版支持的布局样式后，预览体现修改。 |
| A03 | 保存并再次打开 | 已保存的内容与页面配置可以继续编辑，草稿仍仅作者可见。 |
| A04 | 使用模板组织不同主题 | 不被租房字段或固定章节限制；首版选定的区块及布局可修改。 |
| A05 | 保存并应用模板（若首版采纳） | 保留所选择的结构与样式；作者正文是否复制符合其明确选择。 |
| A06 | AI 失败或重新整理 | 原始资料和已有编辑保留；重试不产生重复作品，接受修改前不覆盖已有成果。 |
| A07 | 使用默认值创建 | 未选择模板、封面或自定义配色，且已确认建议人群或“不限定人群”时，仍能完成草稿创建。 |
| A08 | 桌面与手机预览 | 内容可读，核心编辑有可操作入口；分栏能合理适配手机，无非预期横向溢出。 |
| A09 | 公开发布与账号隔离 | 作者明确发布前其他用户不可见；用户不能修改他人草稿、模板或页面配置。 |
| A10 | 对话后打开并修改问卷 | 人群、用途及带具体说明的风格可选择、补充和修改；确认摘要体现最终答案，关闭再打开不丢已填写答案。 |
| A11 | 确认问卷后生成 | 作者所选人群、用途及风格能在方案与预览中核对；不支持的样式要求有提示，修改答案后旧结果不能冒充新答案的结果。 |
| A12 | 自由画布定位与缩放 | 模块位置、尺寸可调整和保存；手机内容仍可读，切回桌面保留构图，阅读顺序有独立操作。具体适配规则待评审。 |
| A13 | 代码创建区块 | 粘贴 HTML + CSS 或导入 UTF-8 HTML 文件，检查后添加时间轴等模块，可编辑源码、移动和保存；不用为每个视觉样式新增业务组件。 |
| A14 | 导入错误及预览一致性 | 空白、无正文、超限、不支持标签/属性或无效文件有错误说明；改源码后不能应用旧检查；取消不改现有模块。 |
| A15 | 编辑、保存及再次打开 | 源码编辑保留 ID、阅读顺序及布局；保存刷新后原文、显示高度和布局恢复；旧的普通区块草稿仍可使用。 |
| A16 | 代码隔离和适配 | 自定义样式仅影响模块；脚本/事件/外部资源被拒绝，渲染另有沙箱限制。390px 手机容器堆叠并保留桌面构图；作者负责内部响应式，内容可滚动。 |

第一次迭代验收优先考虑 A10、A11、A01、A03、A06、A07，并从 A02/A08 中选择首版实际开放能力。A04/A05 与完整搭建能力按后续范围验收。A09 涉及的私人草稿归属约束始终适用，公开发布不自动列入首轮终点。

“快速”先通过真实试用记录首次成稿时间、需要的操作和阻塞点；本轮不把任意分钟数写成已确认指标。确认首版范围与原型后，再确定可重复的时间目标和测试材料。

## 10. 范围与待确认事项

目前已确认快速迭代、创建问卷、私人草稿终点、自由画布和静态 HTML + CSS 自定义模块；字段规则、正式首轮组件和风格仍待确认。完整搭建能力分轮细化。自动联网搜集资料、任意 JavaScript/Vue 文件运行、完整网页抓取还原、多人协作及模板交易不在本轮范围。现有格式导入也不等于已支持 PDF、Word、图片识别或复杂网页抓取。

| 编号 | 待决定事项 | 建议起点（未确认） | 影响 |
| --- | --- | --- | --- |
| Q01 | 首轮支持哪些区块 | 最少区块先跑通生成与修改，复杂类型后续评审 | 决定编辑和展示复杂度 |
| Q02 | 首轮风格选项和可编辑设置 | 少量带具体说明的预设，后续开放更多布局与样式 | 决定原型与手机适配 |
| Q03 | 模板保存与共享安排在哪轮 | 首轮可先使用系统预设；个人保存及公开分享后续评审 | 决定模板归属、复用及隐私 |
| Q04 | 首版 AI 输入资料格式及大小 | 沿用粘贴文字与 TXT/Markdown，其他格式另评估 | 决定导入操作与失败处理 |
| Q05 | AI 怎样处理原文及新增建议 | 默认整理已有资料，原文可核对，新增建议需区分 | 决定生成结果的可审阅性 |
| Q06 | 使用哪种 AI 服务及使用边界 | 概设阶段比较；先明确数据发送、费用与失败路径 | 决定外部接入与运行条件 |
| Q07 | 首版试用指标与验收材料 | 用租房和另一主题固定资料验证，先测成稿时间 | 决定“快速”和“通用”的验收依据 |
| Q09 | 问卷字段与必答规则 | 主题、人群、用途及风格需要确认，其他按需补充 | 决定准确性和填写负担 |
| Q10 | 尚无资料时的处理 | 可先确认问卷与空结构，实际内容标为待补充 | 决定起稿入口与生成职责 |
| Q11 | 自由画布适配、重叠与尺寸规则 | 手机按阅读顺序堆叠并保留桌面布局，继续评审层级及尺寸保护 | 决定不同设备的可读性与编辑范围 |
| Q13 | 后续高级扩展及代码模块复用 | Vue 插件、Markdown 指令、Mermaid、结构化表单与源码互转另行评估 | 决定新增交互、依赖及兼容范围 |

Q08（首轮终点）已确认，转为 D09；Q12 的首轮入口已确定为 HTML + CSS，转为 D11/D12，原 Markdown 指令建议被替代，扩展能力留在 Q13。Q09、Q10、Q02 优先用于确认问卷；Q01、Q04、Q05 随正式首轮范围确定；Q03 可后续迭代。Q06 在外部接入前确定，Q07 在原型验收前确定。未决选择不得被下一位 AI 默认为已批准。
