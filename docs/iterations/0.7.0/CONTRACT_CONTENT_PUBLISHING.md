## 1. 对概设的细化与偏差（均不改变用户可见流程）

| # | 概设 | 契约 | 理由 |
| --- | --- | --- | --- |
| 1 | 状态键`ARTICLE:<draftId>` | **`ARTICLE#<draftId>`** | 既有键是`ARTICLE:`+客户端任意字符串（≤64字符），`ARTICLE:5`之类会与新键撞车（复评#4）；`#`前缀客户端键永不产生，免去迁移前的碰撞预处理。 |
| 2 | 发布结果按`respond()`返回201/202 | 新接口一律**HTTP 200**，由`outcome`区分 | 简化前端；旧`POST /api/posts`移除，无第三方客户端承诺。 |
| 3 | 草稿`author_id`随用户删除级联 | 外键**不级联**（与`content_posts.author_id`一致），用户为停用而非删除 | 避免误删用户时静默删稿。 |
| 4 | 草稿时间列类型未定 | `timestamp with time zone` | 与`content_posts.created_at`同型，回填无需转换。 |
| 5 | 幂等写入草稿 | 草稿加`last_request_id`、`last_request_version` | 落实概设§14.3#1。 |
| 6 | 发布版本号来源未定 | 公开版版本取**最近一条`PUBLISHED`流转的`snapshot_version`**（`content_posts`不新增版本列） | 少改公开表；无流转的历史文章版本为空。 |

## 2. 数据（Flyway `V18__article_drafts.sql`，PostgreSQL；附加+回填）

H2开发/测试默认`flyway.enabled=false`、`ddl-auto: update`（`application.yml`）：`article_drafts`同时提供**JPA实体**，下列PostgreSQL专有约束与回填只在PostgreSQL验证；**H2通过不代表迁移通过。**

```sql
create table article_drafts (
    id bigint generated by default as identity primary key,
    author_id bigint not null references user_accounts(id),
    post_id bigint unique references content_posts(id),
    title varchar(120) not null default '',
    summary varchar(280) not null default '',
    body text not null default '',
    version bigint not null default 1,
    last_request_id varchar(64),
    last_request_version bigint,
    last_request_hash varchar(64),               -- 内容哈希，见§14 R2
    legacy_state_id bigint,                       -- 仅供回填使用，回填后删除
    created_at timestamp with time zone not null,
    updated_at timestamp with time zone not null,
    constraint ck_article_draft_nonempty check (title <> '' or summary <> '' or body <> '')
);
create index ix_article_drafts_author on article_drafts (author_id, updated_at desc, id desc);

alter table content_posts add column updated_at timestamp with time zone;   -- 空=从未被作者更新
alter table content_posts drop constraint if exists content_posts_moderation_state_check;
alter table content_posts add constraint content_posts_moderation_state_check check (moderation_state in ('VISIBLE', 'TAKEN_DOWN', 'WITHDRAWN'));

alter table review_audit_log drop constraint if exists review_audit_log_type_check;
alter table review_audit_log add constraint review_audit_log_type_check
    check (type in ('SUBMIT', 'APPROVE', 'REJECT', 'UPHOLD', 'OVERTURN', 'TAKE_DOWN', 'RESTORE', 'WITHDRAW', 'RULE_CREATE', 'RULE_UPDATE', 'RULE_DELETE', 'BATCH_RULES', 'IMPORT_RULES', 'NOTED', 'DELETE_DRAFT'));
```
约束名`content_posts_moderation_state_check`来自V15内联CHECK的PostgreSQL默认命名，**演练时先`\d content_posts`核对实际名称**，名称不符则按实际名删除（未核实项）。

### 2.1 回填（同一迁移内，顺序执行；Flyway只执行一次，回填语句各带保护条件，但C末尾删除辅助列后不可单独重跑）

**A 已发布文章建稿**：
```sql
insert into article_drafts (author_id, post_id, title, summary, body, version, created_at, updated_at)
select p.author_id, p.id, p.title, p.summary, p.body, 1, p.created_at, p.created_at
from content_posts p
where p.type = 'ARTICLE' and not exists (select 1 from article_drafts d where d.post_id = p.id);
```
**B 已发布文章的审核状态改键，缺则补**：
```sql
update review_content_state s
   set content_key = 'ARTICLE#' || (select d.id from article_drafts d where d.post_id = s.target_id), updated_at = now()
 where s.content_type = 'ARTICLE' and s.target_id is not null and s.content_key not like 'ARTICLE#%'
   and exists (select 1 from article_drafts d where d.post_id = s.target_id and d.author_id = s.author_id);

insert into review_content_state (author_id, content_type, content_key, target_id, attempts, generation, approved_once, legacy, created_at, updated_at)
select d.author_id, 'ARTICLE', 'ARTICLE#' || d.id, d.post_id, 0, 1, true, true, now(), now()
from article_drafts d
where d.post_id is not null and not exists (select 1 from review_content_state s where s.content_type = 'ARTICLE' and s.author_id = d.author_id and s.content_key = 'ARTICLE#' || d.id);
```
**C 在途未发布提交补建草稿（PUBLISH-D07）**：仅处理“有至少一条提交”的状态；没有任何提交的空状态（`lockState`独立事务可能留下）**跳过**。
```sql
insert into article_drafts (author_id, post_id, title, summary, body, version, legacy_state_id, created_at, updated_at)
select s.author_id, null, left(coalesce(x.snap->>'title', ''), 120), left(coalesce(x.snap->>'summary', ''), 280), coalesce(x.snap->>'body', ''), x.snapshot_version, s.id, x.created_at, now()
from review_content_state s
join lateral (select r.snapshot_json::jsonb as snap, r.snapshot_version, r.created_at from review_submissions r where r.state_id = s.id order by r.id desc limit 1) x on true
where s.content_type = 'ARTICLE' and s.target_id is null and s.content_key not like 'ARTICLE#%'
  and (coalesce(x.snap->>'title','') <> '' or coalesce(x.snap->>'summary','') <> '' or coalesce(x.snap->>'body','') <> '');

update review_content_state s set content_key = 'ARTICLE#' || d.id, updated_at = now()
  from article_drafts d where d.legacy_state_id = s.id;
alter table article_drafts drop column legacy_state_id;
```
（V18为PostgreSQL专用脚本，`UPDATE … FROM`在PostgreSQL合法；H2不执行该脚本。）旧待审任务保持`PENDING`并仍属该状态；其快照以后经`decide`首次发布时按§3.7写回草稿。**回填后断言（演练必跑）**：
1. `select count(*) from content_posts where type='ARTICLE'` = `select count(*) from article_drafts where post_id is not null`。
2. 不存在`review_content_state(content_type='ARTICLE')`且`content_key not like 'ARTICLE#%'`且（`target_id is not null`或存在提交）的行。
3. `article_drafts`中`post_id is null`的行数 = 有提交**且快照三项不全空**的未发布状态数（全空快照按C的条件被跳过）。
4. **迁移前**只读探测：同一作者的ARTICLE状态里`target_id`重复数应为0（`target_id`无唯一约束，重复会令改键后`post_id`关联不唯一）；重复须先处理，不得靠迁移失败来发现。键唯一性由`ux_review_state_key`保证。
5. 畸形快照（`snapshot_json::jsonb`失败）数为0——**若转型失败迁移整体回滚**，演练时先用只读查询探测。

## 3. 服务规则

引入类（命名示意，G5可调整但职责不变）：`ArticleDraftService`（草稿读写，非事务入口）、`ArticleDraftWriter`（独立Bean，`REQUIRES_NEW`保存，避免同类自调用绕过代理）、`ReviewService.submitArticleDraft`、`TextLimits`（码点计数）。

### 3.0 通用
- 身份取自`AuthController.requireUser`（会话、停用、`sessionEpoch`均检查，失败401）；权限`@RequirePermission(Permission.POST_CREATE)`；他人资源一律404（不泄露存在性）；写请求受现有CSRF保护（无/错令牌403）。
- 文本限制：标题≤120、摘要≤280、正文≤20000，**按Unicode码点**（`String.codePointCount`），不用`@Size`；`requestId`≤64字符；超限400`TOO_LONG`并返回`field,max,actual`。`ReviewText.cut`改为码点安全截断（`offsetByCodePoints`）。
- **加锁顺序统一：草稿行 → 状态行（`review_content_state`）→ 公开行（条件UPDATE）。** 审批`decide`先由键`ARTICLE#<id>`解析草稿ID并先锁草稿再锁状态，避免与作者路径互锁。

### 3.1 创建 `POST /api/me/articles`
校验限制；标题/摘要/正文全部为空（trim后）→400`EMPTY_DRAFT`；插入`version=1`；返回`ArticleView`。创建不触发检测、不建状态行。

### 3.2 保存 `PUT /api/me/articles/{id}`
事务：`select … for update`草稿（非本人404）→ `expectedVersion != version` →409`VERSION_CONFLICT`（`extra.currentVersion`）→ 内容与现有一致则**不加版本、不改时间**，否则`version+1`、`updated_at=now()` → 返回视图。已下架文章**允许保存**（保存不改公开状态）。允许缺字段，但三项全空→400`EMPTY_DRAFT`。

### 3.3 发布/更新 `POST /api/me/articles/{id}/publish`
入口控制器**不加事务**。
1. 校验限制与必填（标题/摘要/正文trim后非空）→400`VALIDATION`（`fields`列出缺项）。
2. **回执回放**：按`(状态键ARTICLE#id, requestId)`查`review_receipts`，命中→返回已存结果，`replay=true`，不保存、不检测。
3. **保存事务（`ArticleDraftWriter`，`REQUIRES_NEW`，提交后返回）**：锁草稿；若`last_request_id = requestId`→**跳过版本校验与保存**（同一请求的重试）；否则校验`expectedVersion`（不符409）；内容变化则`version+1`；写`last_request_id/last_request_version`。
4. **提交事务（`submitArticleDraft`）**：先`rules.detect`（无启用规则/异常→503`DETECTION_UNAVAILABLE`，此时尚无任何状态/流转，**已保存草稿保持**）；锁状态（缺则在独立事务创建）；再查回执；公开行`moderation_state='TAKEN_DOWN'`→409`TAKEN_DOWN`；使旧待审任务失效；建流转与事件；按级别：
   - **NONE/LOW**：`publishOrUpdate`（§3.6），流转`PUBLISHED`；LOW写留痕；
   - **MEDIUM**：建`REVIEW`任务，结果`PENDING`；
   - **HIGH**：建`RECHECK`任务，流转`AUTO_REJECTED`，响应不含命中词。
   写回执、审计、状态`generation+1`。
5. 响应`PublishResult`（HTTP 200）。重复提交（不同`requestId`）会使旧待审任务失效，不重复发布。

### 3.4 取消送审 `POST /api/me/articles/{id}/cancel`
锁草稿→状态；取该状态`PENDING`任务：无→409`NOTHING_TO_CANCEL`；`kind='RECHECK'`→409`RECHECK_NOT_CANCELLABLE`（“高敏感已转人工复核，不能取消，可改稿重提”）；否则任务置`INVALID`（原因“作者取消送审”）、流转置`INVALID`并追加`RESULT`事件“已取消送审”、`generation+1`、审计`WITHDRAW`（note“作者取消送审”）。工作稿与公开行不变。**不复用`withdrawTask`的无保护实现**，在其上补`kind`保护与事件（见§7）。

### 3.5 撤回 `POST /api/me/articles/{id}/withdraw`
`confirm`不为`true`→400`CONFIRM_REQUIRED`。锁草稿→状态；公开行：不存在→409`NOT_PUBLIC`；`TAKEN_DOWN`→409`TAKEN_DOWN`；已`WITHDRAWN`→409`NOT_PUBLIC`；`VISIBLE`→使待审任务失效、`update content_posts set moderation_state='WITHDRAWN' where id=? and moderation_state='VISIBLE'`（0行→409）、事件“作者撤回”追加到**最近一条`PUBLISHED`流转**（无流转的历史文章先创建一条合成流转：`PUBLISHED`、`level='NONE'`、标题取公开标题、`snapshot_version`取草稿版本，仅承载该事件，不补造`SUBMIT/CHECK`）、`generation+1`、审计`WITHDRAW`。重新发布走§3.3，**重新检测**，旧审核结论不恢复公开。

### 3.6 `publishOrUpdate(state, snapshot)`（发布与审批通过共用，状态锁内）
- 状态`target_id`为空 → 插入`content_posts`（`type='ARTICLE'`）并写`review_submission_id`；写回`article_drafts.post_id`与状态`target_id`。
- 已有`target_id` → **条件UPDATE**：`update content_posts set title=?,summary=?,body=?,updated_at=now(),moderation_state='VISIBLE',review_submission_id=? where id=? and moderation_state in ('VISIBLE','WITHDRAWN')`；0行（说明`TAKEN_DOWN`）→409`TAKEN_DOWN`并使对应任务失效。**不`save`整个实体**（避免整行回写覆盖并发状态），`createdAt`、`likes`、评论不变。

### 3.7 审批 `decide`（既有，ARTICLE分支调整）
批准/误判放行时调用§3.6；`WITHDRAWN`的公开行被批准更新时改回`VISIBLE`（等同重新公开，已过检测与审批）；`TAKEN_DOWN`中止并使任务失效。首次发布（状态`target_id`空）须写回草稿`post_id`（修复现状：目前只新建帖）。任务`generation`与`expectedGeneration`校验、禁止自审、独立权限保持不变。

### 3.8 处置 `manage`（既有，补护栏）
仅`VISIBLE`↔`TAKEN_DOWN`：对`WITHDRAWN`的`TAKE_DOWN`与`RESTORE`均409`NOT_PUBLIC`；审批侧`publications`列表、详情与`publishedView`排除`WITHDRAWN`。

### 3.9 删除 `DELETE /api/me/articles/{id}`
锁草稿→状态。`post_id`非空（公开过/已撤回/已下架）→409`NOT_DELETABLE`（`reason=PUBLISHED_BEFORE`）；存在`PENDING`任务→409`NOT_DELETABLE`（`reason=PENDING_SUBMISSION`）。**同一事务内显式按序删除**（H2无外键级联）：`review_flow_events`（按本状态各流转）→`review_flows`→`review_submissions`→`review_receipts`→`review_content_state`→`article_drafts`；写审计`DELETE_DRAFT`（`content_id`=草稿ID，`note`仅“删除私人草稿”，**不含标题/正文**）。成功200`{message}`；重复删除404。断言“库内无该稿正文”在PostgreSQL上做。

### 3.10 其他修复（CT-A11/A12的前置，纳入G5）
- 点赞：`update content_posts set likes=likes+1 where id=? and moderation_state='VISIBLE'`，0行→404；响应读取更新后的行。
- 专题收录：`CollectionWorkspaceController`的POST条目校验要求被引文章`moderation_state='VISIBLE'`且作者一致，否则400“该文章未公开，不能收录”；`CollectionPublicationService.capture`只冻结`VISIBLE`文章的标题摘要，非可见条目按“不可用”占位；已存在的草稿引用按专题修订2显示失效引用。
- `PersonalController.posts`的文章部分由`GET /api/me/articles`取代。

### 4.1 DTO

```
ArticleRow   { id, postId|null, title, summary, version, status:{publicState, work}, updatedAt,
               hasPublished, publicTitle|null, canCancel, canWithdraw, canDelete }
ArticleView  { id, postId|null, title, summary, body, version, createdAt, updatedAt,
               status:{publicState: NONE|LIVE|WITHDRAWN|DOWN, work: PRIVATE|SAVED|MODIFIED|REVIEWING|RECHECK|REJECTED},
               published:{title, summary, body, version|null, updatedAt|null}|null,   // 来自content_posts；读者“现在看到”
               submitted:{version, title, summary, body, kind: REVIEW|RECHECK, level, submittedAt}|null, // 待处理任务的冻结快照；不含命中词
               canCancel, canWithdraw, canDelete,
               flows:[FlowView≤5] }                                                    // 即既有authorFlow：{id,type,title,version,level,status,startedAt,events[],taskId}
PublishResult{ outcome: PUBLISHED|PENDING|AUTO_REJECTED, level: NONE|LOW|MEDIUM|HIGH, message, flowId, taskId|null,
               replay: boolean, article: ArticleView }                                 // HIGH时不含命中词/详情
```
**状态推导**（服务端，与原型`compositeStatus`一致）：`publicState`——无`post_id`=`NONE`；公开行`VISIBLE`=`LIVE`、`WITHDRAWN`=`WITHDRAWN`、`TAKEN_DOWN`=`DOWN`。`work`——存在`PENDING`任务：`kind=RECHECK`→`RECHECK`，否则`REVIEWING`；否则最近流转为`REJECTED`/`UPHELD`→`REJECTED`；否则`publicState=LIVE`且草稿与公开行（标题/摘要/正文）不同→`MODIFIED`；否则无公开行且无流转→`PRIVATE`；其余`SAVED`。`canCancel`=存在`REVIEW`类`PENDING`任务；`canWithdraw`=`LIVE`；`canDelete`=`post_id`为空且无`PENDING`任务。

## 6. 并发与幂等矩阵

| 竞态 | 裁决 |
| --- | --- |
| 作者两次保存 | 草稿行锁+`expectedVersion`；后者409，输入由前端保留 |
| 同`requestId`重复发布/超时重试 | 回执回放；保存对同`requestId`幂等，不重复发布、不撞版本 |
| 新`requestId`重复发布 | 使旧待审任务失效；已发布内容按§3.6更新同一行，不新建 |
| 发布 vs 取消送审 | 草稿→状态锁序列化；取消后任务`INVALID`，发布再建新任务 |
| 审批通过 vs 作者重提/撤回/取消 | `decide`锁序一致；任务`generation`/状态不符→409`STALE`，不发布 |
| 作者更新 vs 人工下架 | 条件UPDATE仅作用于`VISIBLE/WITHDRAWN`；对`TAKEN_DOWN`→409，不覆盖下架 |
| 点赞 vs 撤回/下架/改稿 | 原子`likes=likes+1`且仅`VISIBLE`；不写回其它列 |
| 删除 vs 发布 | 草稿行锁序列化；先发布则删除409`NOT_DELETABLE`；先删除则发布404 |
| 撤回 vs 审批批准 | 撤回使待审失效并`generation+1`；批准按`generation`409 |
