## 1. 与原型 R2 的偏差（均不改变用户可见流程）

| # | R2 | 契约 | 原因 |
| --- | --- | --- | --- |
| 1 | 评审队列页大小 6、规则页 8，演示数据在浏览器 | 队列与规则页大小均为 `size` 参数（默认 10，上限 50），服务端分页 | 真实数据量；页面“每页条数”以服务端为准 |
| 2 | 演示设置（检测失败、慢加载等）与“审核演示”面板 | 不进入生产；失败状态来自真实错误 | 演示工具 |
| 3 | 恢复时命中词：一键恢复（原型忽略命中） | 恢复命中时首次返回 409 列出命中词，审批者带 `acknowledgeMatches=true` 重新提交才恢复 | 把“命中则合并敏感复审”落成可审计的显式确认，页面多一个确认弹窗，其余流程不变 |
| 4 | 作者侧“审核提交”演示页 | 生产在发布表单就地展示 `outcome`，另设 `/me/reviews` 只读状态页 | 原型页只是 F08 片段（原型文档已声明） |
| 5 | 模拟用户 ID、内容 ID 为内存数字 | 内容键 `ARTICLE:`/`COMMENT:` 前缀 + draftKey，专题 `COLLECTION:<id>` | 新文章/评论发布前无服务端 ID |

## 2. 数据（Flyway `V15__content_review.sql`，附加变更）

```sql
-- 公开表下架状态（默认可见）
alter table content_posts add column moderation_state varchar(10) not null default 'VISIBLE' check (moderation_state in ('VISIBLE','TAKEN_DOWN'));
alter table comments add column moderation_state varchar(10) not null default 'VISIBLE' check (moderation_state in ('VISIBLE','TAKEN_DOWN'));
alter table community_collections add column moderation_state varchar(10) not null default 'VISIBLE' check (moderation_state in ('VISIBLE','TAKEN_DOWN'));
alter table content_posts add column review_submission_id bigint;   -- 批准发布时的来源提交，旧内容为空
alter table comments add column review_submission_id bigint;

create table sensitive_rules (
  id bigint generated by default as identity primary key,
  phrase varchar(40) not null,
  note varchar(200) not null default '',
  enabled boolean not null default true,
  deleted boolean not null default false,

create unique index ux_sensitive_rules_active on sensitive_rules (active_key) where active_key is not null;

create table review_content_state (
  id bigint generated by default as identity primary key,
  author_id bigint not null references user_accounts(id) on delete cascade,
  content_type varchar(12) not null check (content_type in ('ARTICLE','COMMENT','COLLECTION')),
  content_key varchar(80) not null,
  target_id bigint,                           -- 已发布/已存在的公开对象 ID
  attempts int not null default 0,
  generation bigint not null default 1,

  legacy boolean not null default false,
  created_at timestamp not null, updated_at timestamp not null,
  unique (author_id, content_type, content_key));

create table review_submissions (
  id bigint generated by default as identity primary key,
  state_id bigint not null references review_content_state(id) on delete cascade,
  author_id bigint not null references user_accounts(id) on delete cascade,
  content_type varchar(12) not null,
  generation bigint not null,
  snapshot_json text not null,                -- 不可变；专题为冻结快照
  snapshot_version bigint not null,
  triggers varchar(30) not null,              -- FIRST / SENSITIVE / FIRST,SENSITIVE
  matched_phrases varchar(400) not null default '',
  attempts int not null,
  status varchar(10) not null check (status in ('PENDING','APPROVED','REJECTED','INVALID')),
  result_note varchar(200) not null default '',
  operator_id bigint, operator_name varchar(40),
  created_at timestamp not null, closed_at timestamp);
create index ix_review_sub_status on review_submissions (status, created_at desc, id desc);
create index ix_review_sub_author on review_submissions (author_id, created_at desc, id desc);

create table review_receipts (
  state_id bigint not null references review_content_state(id) on delete cascade,
  request_id varchar(64) not null,
  response_json text not null,
  created_at timestamp not null,
  primary key (state_id, request_id));

create table review_audit_log (
  id bigint generated by default as identity primary key,
  type varchar(14) not null check (type in ('SUBMIT','APPROVE','REJECT','TAKE_DOWN','RESTORE','WITHDRAW','RULE_CREATE','RULE_UPDATE','RULE_DELETE')),
  outcome varchar(10) not null default 'SUCCESS' check (outcome in ('SUCCESS','REJECTED','FAILED')),
  operator_id bigint, operator_name varchar(40),
  author_id bigint, content_type varchar(12), content_id bigint, submission_id bigint,
  snapshot_version bigint, triggers varchar(30),
  phrase varchar(40), rule_enabled boolean,
  note varchar(200), result_message varchar(200),
  created_at timestamp not null);
create index ix_review_audit_time on review_audit_log (created_at desc, id desc);

-- 内容审批权限：OWNER 角色自动拥有
insert into role_permissions (role_id, permission)
select r.id, 'content.review' from roles r where r.system_kind='OWNER'
  and not exists (select 1 from role_permissions x where x.role_id=r.id and x.permission='content.review');
```

### 2.1 `V16__sensitive_rule_match_mode.sql`（需规修订5）

```sql
alter table sensitive_rules add column match_mode varchar(10) not null default 'SUBSTRING' check (match_mode in ('SUBSTRING', 'WHOLE_WORD'));
```

实体 `SensitiveRuleEntity` 增加同名字段（H2 建表与 PG validate）。规则接口：`RuleRequest`/`Rule` 增加 `matchMode`（缺省为子串；非法值 400）；规范化后为空的词语 400“规则只包含标点或空白…”。`active_key` 仍保存规范化词语用于唯一性，**检测时不依赖它**，而是由 `phrase` 现算，避免规范化规则变化后历史行失配。

## 3. 服务规则

### 3.1 `ContentReviewService.submit(author, type, contentKey, requestId, snapshot)`（一个事务）

1. 检测可用性：启用规则数为 0 或读规则异常 → 503，`code=DETECTION_UNAVAILABLE`，无计数/任务/回执写入（私人保存路径不经本服务）。
2. 取/建 `review_content_state` 行（唯一键冲突则重读）→ `select … for update`。
3. 回执：同 `requestId` 已存在 → 原样返回首次响应，不重复计数。
4. 作者校验：账号 ACTIVE；若 `taken_down`（`target_id` 对应公开行 `moderation_state=TAKEN_DOWN`）→ 409 `TAKEN_DOWN`“内容已下架，保存或发布不能解除下架，请等待人工复核恢复”。
5. 命中词 = 规范化后子串匹配。
6. 分支：
   - **无命中**：`attempts=0`、`generation+1`、旧 PENDING→INVALID。文章/评论：写公开行，`outcome=PUBLISHED`。专题且 `!approved_once`：建 `FIRST` 任务（`PENDING`）。其余专题：冻结发布（§3.3）。
   - **命中且 `attempts+1<3`**：`attempts+1`，`outcome=BLOCKED`，返回 `attempts`、`matches`、说明；不建任务；不改 generation。
   - **命中且 `attempts+1>=3`**：`attempts+1`、`generation+1`、旧 PENDING→INVALID，建任务（专题首次发布为 `FIRST,SENSITIVE`，其余 `SENSITIVE`），`outcome=PENDING`。
7. 写回执与 `SUBMIT` 记录。失败（异常）整体回滚；`FAILED` 记录在独立事务。

### 3.2 `decide(operator, taskId, action, expectedGeneration, note)`（一个事务）

重读操作者：ACTIVE 且当前持有 `content.review`，否则 403 `FORBIDDEN`。任务不存在 404。锁 `review_content_state` 行。`task.author_id==operator.id` → 403 `SELF_REVIEW`“禁止审核本人内容”。作者非 ACTIVE、`task.status!=PENDING` 或 `generation` 不符 → 409 `STALE`（作者非 ACTIVE 同时把任务置 INVALID）。`REJECT` 必须 `note`（≤200 字）。`APPROVE`：文章/评论插入公开行（`review_submission_id`）；专题按 §3.3 发布快照；`approved_once=true`（专题）、`attempts=0`、`generation+1`、同对象其他 PENDING→INVALID；任务置 APPROVED。`REJECT`：任务置 REJECTED，`attempts` 不清零，旧发布版不变。均写记录。

### 3.3 专题冻结发布（`CollectionPublicationService.publishFrozen`，新增）

接收提交时冻结的 `PublicOutline` JSON，写 `collection_publications`（覆盖，visibility 取快照中的 visibility）、置 `community_collections.status='PUBLISHED'`、`published_at`；**不修改工作稿行**，`revision` 仅在当前 `revision` 不高于快照提交时才 `+1`，否则保持（避免批准把作者更新的工作稿版本号倒退）。受限可见性在提交时按作者当前角色校验（沿用 `canRestrict`），批准时不重做该校验（快照已冻结）。直接发布（无命中且有首次资格）与批准都调用此方法。现有 `publishSnapshot(long)` 保留给 V7 迁移与演示数据，不经审核。

### 3.4 处置 `managePublication(operator, type, targetId, action, expectedModeration, expectedVersion, note, acknowledgeMatches)`

要求 `content.review`；`note` 必填；`RESTORE` 禁止作者本人（403 `SELF_REVIEW`）；`TAKE_DOWN`/`RESTORE` 与当前 `moderation_state` 不符 409。`TAKE_DOWN`：公开行置 TAKEN_DOWN，`generation+1`，旧 PENDING→INVALID（下架优先）。`RESTORE`：重新检测当前发布内容（文章/评论取公开行，专题取 `collection_publications.document` 的文本）；有命中且 `acknowledgeMatches!=true` → 409 `MATCHED`（含命中词）；检测不可用 → 503；否则置 VISIBLE。均写记录。

### 3.5 其他生命周期

作者撤回专题（现有 archive）或评论删除：`generation+1`、PENDING→INVALID，写 `WITHDRAW`。账号停用：任务在读取/处理时惰性失效（§3.2）。恢复账号不自动重开任务。已发布内容不因账号停用隐藏。

### 3.6 规则服务

读取与全部写入要求**当前站长**（`access_control_state.owner_user_id` 在事务内读取，不是 `content.review`）。`create`：规范化 `active_key` 冲突 → 400“此词或短语已存在，请直接编辑原规则”。`update/delete/toggle`：`where id=? and version=? and deleted=false` 条件更新，0 行 → 409。删除：`deleted=true, enabled=false, active_key=null, version+1`。每次写规则记 `RULE_*` 记录。启用规则上限 500，超出 400。

## 4. 接口（`/api/review`，写请求带 CSRF；均为 JSON）

错误体沿用 `ApiProblem`：`{status,message}`，另加 `code` 字段承载 §3 中的机器码。

### 4.1 作者侧

- `POST /api/review/submissions`（登录 + 对应创作权限：ARTICLE→`post.create`，COMMENT→`post.interact`，COLLECTION→`collection.manage`）：`{type, contentKey, requestId, title?, summary?, body, postId?(评论所属), collectionId?, collectionRevision?}` → `{outcome: PUBLISHED|BLOCKED|PENDING, attempts, matches[], taskId?, targetId?, message}`。服务端从会话取作者，忽略任何客户端 `authorId`。
- `GET /api/review/mine?page&size` → 本人提交与任务状态、驳回原因、下架状态；仅本人。
- `POST /api/review/mine/{taskId}/withdraw`：本人撤回待审任务。

### 4.2 审批侧（`content.review`）

- `GET /api/review/queue?status=PENDING|DONE|ALL&type&trigger&days&q&page&size` → `{items,total,page,size,pending,first,sensitive}`。
- `GET /api/review/tasks/{id}` → 任务、快照、当前发布版（首次为空）、`otherReviewerAvailable`、`self`、历史。
- `POST /api/review/tasks/{id}`：`{action: APPROVE|REJECT, expectedGeneration, note}` → `{message}`。
- `GET /api/review/publications?type&state&q&page&size`、`GET /api/review/publications/{type}/{id}`；`POST /api/review/publications/{type}/{id}`：`{action: TAKE_DOWN|RESTORE, expectedModeration, expectedVersion, note, acknowledgeMatches?}`。
- `GET /api/review/audit?…`：处置与审批记录（不含规则变更）；不开放 `admin.audit`。

### 4.3 规则侧（当前站长）

- `GET /api/review/rules?q&status=ENABLED|DISABLED&page&size` → `{items:[{id,phrase,note,enabled,version,updatedAt}],total,page,size,enabledCount,disabledCount}`；`GET /api/review/rules/history?page&size`。
- `POST /api/review/rules`：`{phrase,note,enabled}` 新增；`PUT /api/review/rules/{id}`：同字段 + `expectedVersion`；`PATCH /api/review/rules/{id}/enabled`：`{enabled, expectedVersion}`；`DELETE /api/review/rules/{id}`：`{expectedVersion}`。

### 4.4 权限与 CSRF 矩阵

游客 401；无权限 403；停用账号 401（会话规则）；伪造 `authorId`/他人任务 ID 无效或 404；规则接口非站长 403（即使有 `content.review`）；无/错 CSRF 403。

## 5. 记录字段映射

`review_audit_log.type` 对应 §3 各操作；`triggers` 取任务触发类型，`RESTORE` 命中时填 `RESTORE,SENSITIVE`；`note` 为原因/说明；`result_message` 为拒绝或失败原因。

## 6. 前端（`frontend/src`）

路由与页面见概设 §3.9；`api()` 已携带 HTTP 状态与登录失效面板（FINNS-15），本项的编辑表单（规则新增/编辑、审批原因）接入 `useSessionGuard`，提交前核对账号。规则删除需确认弹窗并显示具体词语；列表筛选保留 URL 查询参数以支持刷新与前进后退。

## 8. 兼容性

**H2 建表来源**：测试/默认 H2 配置 `ddl-auto` 为 `create-drop`/`update`，表结构来自 JPA 实体而非 Flyway（现有 `access_audit_log` 即由 `AccessAuditEntry` 实体提供）。因此 §2 的五张新表和三张公开表新增列须有对应实体/字段映射（列名、类型与 V15 一致），PG 的 `validate` 才会通过；否则 H2 测试缺表。该要求转入 G5（评审条件 C1）。

附加迁移；旧包回退见概设 §4；`content_posts.review_submission_id` 等新列不影响现有实体映射（实体不映射它们时 `ddl-auto=validate` 仍通过，需在 G5 验证）。演示数据与 V7 迁移的专题发布不经审核。

## 9. 容量与限制

规则词语 1–40 字（规范化后须非空）、备注 ≤200 字、启用规则 ≤500；匹配方式 SUBSTRING/WHOLE_WORD；原因/说明 ≤200 字；`requestId`、`draftKey` ≤64 字符；快照 JSON ≤1 MB（文章正文已有 20000 字上限，专题冻结快照沿用现有结构限制）；分页 `size` 1–50。

### 13.2 服务规则变更

1. `SensitiveMatcher.match` 返回 `List<Hit(phrase, level)>`；`detect` 额外返回最高等级。**编译后的自动机按“启用规则指纹”缓存**（指纹 = 启用规则数 + `max(updated_at)` + `sum(version)`，每次检测前用一条聚合查询比对；指纹变化才重建），避免每次提交重建；多实例各自缓存，规则变更后下一次检测即生效。
2. `process`：按 §8.1 分流；无命中/低 → 发布（低额外写 `review_noted`）；中 → `REVIEW` 任务；高 → `RECHECK` 任务 + 流转状态 `AUTO_REJECTED`；每步写 `review_flow_events`。不再有 `BLOCKED`，不再计数；`requestId` 回执与 `generation` 并发裁决保持。
3. `decide`：`REVIEW` 任务只接受 `APPROVE/REJECT`；`RECHECK` 只接受 `UPHOLD/OVERTURN`（均须原因 ≤200 字）；`OVERTURN` 发布提交时的快照；其余校验（禁止自审、权限、generation、作者状态）不变。
4. 专题发布不再因 `approved_once=false` 建 FIRST 任务；`CollectionWorkspaceController.publish` 的返回随之：`PUBLISHED`→200，`PENDING`/`AUTO_REJECTED`→202。
5. 作者撤回/重提/下架使旧任务与进行中的流转置 `INVALID` 并追加 `RESULT` 事件。

### 13.3 接口增量

- `POST /api/posts`、`/api/posts/{id}/comments`、`/api/me/collections/{id}/publish`：响应 `outcome ∈ {PUBLISHED, PENDING, AUTO_REJECTED}`，`flowId`；PENDING/AUTO_REJECTED 为 202，body 含 `message`（高敏感不含命中词）。取消 422 `SENSITIVE_BLOCKED`。

### 13.4 容量与限制

导入：UTF-8 文本，一个或多个文件（文件名=标签、每行一词）或单个 CSV（`词语,标签`）；总大小 ≤2MB、总行数 ≤20000；疑似误报=长度≤2字符，默认不导入；同词多类别保留最高等级；单词 1–40 字；标签 ≤30 字；启用规则上限 **20,000** 条（REVIEW-D23；超出拒绝启用并提示）；分页 `size` 1–50；流转事件说明 ≤200 字、详情 ≤400 字。
