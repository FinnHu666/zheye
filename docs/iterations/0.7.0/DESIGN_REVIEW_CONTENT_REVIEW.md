## 2. 关键主张抽查（对照源码，2026-10-19）

1. 文章/评论目前直接保存（`ContentController.create` 58 行、`comment` 79 行）——**属实**。
2. 专题对外发布只有 `CollectionWorkspaceController.publish`→`publishSnapshot`，另有 V7 迁移与演示数据调用——**属实**，故这两处不经审核（契约 §3.3 已写明）。
3. OWNER 角色权限不可关闭：`Permission.lockedFor` 对 `KIND_OWNER` 返回 true——**属实**，所以新权限只需 V15 给 OWNER 补行。
4. 站长唯一事实源 `access_control_state.owner_user_id`，且 `AccessAdminService` 在锁内重读——**属实**（427/441 行），规则维护可复用同一判定方式。
5. 部分唯一索引可用（`ux_roles_system_kind … where system_kind is not null`）——**属实**（V12 14 行），`sensitive_rules.active_key` 方案同法。
6. 测试 H2 表来自实体——**属实**，已转为 C1。
7. `community_collections.revision` 存在（V6）——**属实**。
8. PG 配置 `ddl-auto: validate`、默认 `update`——**属实**。
9. 三张公开表的读取过滤点已覆盖所有读取路径——**未核实**：仅核对了 `ContentController` 与 `CollectionPublicationService`，搜索/个人主页/收藏的读取点需在 B3 实施前全量检索，列为 C3。

### 6.3 维度结论

1 需求覆盖：RV-A17–A26 均有落点（契约 §13.5），满足。2 取舍：见上。3 现状核对：本节主张已对照源码——`ReviewService.process`、`decide`、`SensitiveMatcher.match` 的现状与 §8 的取消项一致；`approved_once` 仍由 `CollectionWorkspaceController` 的发布路径读取（契约 §13.2-4 已列改动）。4 数据与迁移：V17 全附加；回退旧包不受支持（D16）。5 安全：作者视角剔除高敏感词与审核员姓名在服务端完成，不靠前端隐藏；导入只接受站长上传，限制大小与行数，解析不执行内容。6 并发：流转事件与业务同事务；`RECHECK` 与 `REVIEW` 共用 generation 裁决。7 失败模式：导入文件非法/超限 400 且不写库；批量启停部分失败整体回滚。9 可测试：契约 §13.5。10 范围：未新增产品范围；与 FINNS-18/19 的边界保持。
