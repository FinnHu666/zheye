## 本轮确认及原型方案

用户已回答两项产品选择（USER-ADMIN-D09）：采用“站长可停用/恢复管理员、授予/撤销管理员；管理员只能管理普通成员，不能管理其他管理员及站长”；并要求“允许站长在页面转交站长身份”。R2的固定不可转交假设因此作废，不再等待上述问题的回答。

R3在既有Vue原型中保留共用管理页版式和弹窗，增加独立“转交站长”入口。唯一站长仍不进入普通角色分配选项，不可复制/删除，不通过停用或普通角色调整改变所有者。

以下交互方案已随本次R3整体评审通过，纳入需求修订2；真实安全和持久化实现仍须后续设计：

1. 当前站长在用户页进入转交；从全部正常管理员中选择接任人，不受列表筛选/分页影响。无候选人时提示先恢复或任命管理员；普通成员、停用管理员、自己不可接任。
2. 填写1–200字原因，下一步展示接任人姓名/邮箱、原站长降为管理员、接任人升为唯一站长及权限影响；输入接任人的完整邮箱后才能最终确认。关闭/取消不改变身份。
3. 同步完成双方角色交换和唯一所有者变更，成功/失败/拒绝均留下操作记录。保存失败不改变身份且保留输入；信息冲突重新读取候选人、保留原因，要求重新核对。
4. 成功后原站长本次会话保留为管理员，立即失去站长专属权限；双方其他旧会话失效，接任人须重新登录。资料/作品/私人内容不变。原站长不能自行撤销转交，后续由新站长发起。
5. 页面内邮箱核对用于避免误选，不代表已完成真实密码/MFA再认证；生产身份核验、初始化/迁移、事务锁、通知及异常恢复须在后续设计中明确。

当前G1增量已冻结为需求修订2，G2评审通过；G3以后未推进。旧需规修订1未受影响条款继续有效。新增范围与原型进度的Plane正文增量已准备为[USER-ADMIN-P02待确认差异](../../requirements/FOUNDATION_USER_ADMIN_PLANE_P02.md)，本轮未连接/写Plane，原P01回执只证明旧范围同步。

## 体验步骤

入口：<http://127.0.0.1:4175/admin/users>。左下“用户管理演示 · R3”可载入站长与管理员样例（虚构账号1为站长，周以宁/陈默为管理员，阿远为普通成员）。

1. 以站长点击“转交站长”，选择周以宁、填写原因，核对后输入其演示邮箱，确认。
2. 查看原账号的管理员标记、站长入口消失及管理员/站长对象的禁用按钮；“操作记录”类型选“站长身份转交”。
3. 演示面板点击“切换当前站长”，模拟接任人重新登录：可管理原站长（现管理员），可继续发起交接。此按钮是演示工具，不是产品认证入口。
4. 重新载入样例；勾选“下一次状态保存或转交失败”后转交，检查双方身份未变及已填信息保留。版本冲突、无效CSRF也可用演示开关。
5. 在用户/角色/操作记录间切换；手机尺寸检查转交两步、固定关闭栏及内容滚动。样例按钮会重置本地虚构角色，不代表生产数据操作。
