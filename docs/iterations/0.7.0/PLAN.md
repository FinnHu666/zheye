## 2. 本版功能方向

详见 [多轮需求沟通方案](../../TOPIC_BUILDER_CONVERSATION_PLAN.md)。以下是本版拟落实的可评审范围，具体交互须先制作并确认原型。

| 编号 | 功能描述 | 可观察结果 |
| --- | --- | --- |
| C01 | 连续讨论 | 发送后保持聊天；先回应，再追问最多 1–2 个关键问题；不强制最低轮数 |
| C02 | 可见需求摘要 | 区分用户事实、AI 建议、待定事项；纠正或撤销旧要求时显示变化，不重复索要已明确答案 |
| C03 | 作者主动确认 | AI 建议核对只能提示；只有作者确认当前摘要才进入问卷；保留直接填问卷入口 |
| C04 | 上下文与资料 | 累积摘要加近期原文；作者选择原文加入资料，AI 建议不自动成为事实资料；超限明确提示 |
| C05 | 状态与快照保护 | 取消和迟到响应不覆盖新要求；修改方向使旧确认失效；生成继续使用确认快照，候选接受前不改原稿 |
| C06 | 用量与失败反馈 | 每轮及会话累计用量可查看；未知用量不记零；未配置 Key、超时及非法结果保留输入，不自动重试 |
| C07 | 既有流程兼容 | 问卷、候选、画布、HTML、个人 Key、模块复用、保存和恢复保持原有边界；桌面/390px/768px 可操作 |

技术方向：沿用 Java 17 / Spring Boot / Vue 3 与本人 DeepSeek Key，后端直接调用模型。首版不因多轮对话引入 Agent 框架、联网检索、自动工具调用或新的模型采购。

### 本次纳入的基础能力

| 本版能力 | 可观察结果 | 控制范围 |
| --- | --- | --- |
| 首页全站累计访问量 | 只累计网站访问；站内切换/文章/专题/弹层不重复计数，持久累计及失败明确 | 会话/去重待细化；不做内容对象统计或 UV/完整埋点 |
| 基于角色的访问管理 | 分配用户角色、按角色限制导航/直达/API/内容/操作，变更生效且可审计 | 角色清单/矩阵及可配置性待明确，不扩成继承规则引擎或会员；私人归属仍独立检查 |

这两项先形成独立闭环，为 0.8.0 的评分审核提供基础；不把评价对象/量表数据一起塞入本版。

## 4. 阶段与进入条件

1. **需求评审**：沿用已确认 D01（决定记录 D03），确定 C01–C07 与排除项，记录明确用户决定及修订号；不覆盖旧需规原文。
2. **管理检查点与产品原型**：先处理本版 Plane 具体同步/确认或记录明确延期；当前用户仅要求版本规划，不执行新写入。随后提供三组可体验流程，用户确认原型版本、范围和验收后才进入业务开发。
3. **概要设计**：明确状态机、前后端职责、上下文组织、兼容、身份与回退；以方案为依据核对当前源码。
4. **详细设计与接口契约**：落实 contractVersion、摘要修订、来源/手动答案冲突、容量、错误、取消/迟到及测试映射；涉及 B 才追加持久化设计。
5. **实现与测试**：取得授权后按多轮沟通、统计、管理三个小闭环推进；固定模型常规测试、持久计数/去重/并发验证及多账号/CSRF/撤销测试分开，真实模型按确认预算记录。
6. **验收与发布**：逐项验收、列明未验项；主站部署须有对应授权及可恢复备份/回退证据。发布时才更新四处版本。
7. **交接与 Plane 同步**：按实际证据更新状态与文件索引，Plane 写入逐项确认后回读，不将计划完成登记为功能完成。

严格门禁及产物规则见 [交付流程 skill](../../../.agents/skills/finns-delivery-workflow/SKILL.md)。复用已有明确授权，内部检查不额外索要用户批准；范围发生实质变化才重新评审对应部分。
