# 流程优化记录：需求遗留项、能力边界与“默认选择即上报”

日期：2026-10-20。触发：FINNS-17 检测方案被用户追问后暴露——需规明确“样例词库和误报处理示例由设计阶段提供”“匹配与规范化由设计阶段定义”，设计与自评均未交付、未比较备选、未上报。属流程缺口，不是需求不清。

## 1. 根因

1. 自评只按“十个维度”检查设计本身，没有反向核对**需求里留给设计的承诺**。
2. 把“匹配精度”这类用户可感知的技术选择当作实现细节，默认选了最简方案，没有备选比较，也没有上报。
3. 局限只用一句话带过，没有“具体输入 → 结果 → 能否做到”的能力边界表，用户无法判断。
4. 上线前提（零规则时全部发布被拒）晚到实施记录才出现。

| 场景 | 应触发？ | 走查结果 |

| S1 FINNS-17 概设：需规写“样例词库由设计阶段提供” | 是 | 遗留项提取会命中“设计阶段 / 样例”→ 登记 L1；概设无样例 → “未交付”→ G3 不得通过。**若旧规则生效，第一版的缺口会在评审时被抓到** |
