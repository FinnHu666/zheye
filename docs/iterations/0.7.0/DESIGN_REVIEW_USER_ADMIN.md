# F07 账号停用与用户管理衔接（FINNS-16）概要设计评审

日期：2026-10-18；被评审：[概要设计修订1](DESIGN_USER_ADMIN.md)及对应[契约修订1](CONTRACT_USER_ADMIN.md)；评审者：**同作者自评，独立性有限**（本轮没有授权启动独立子代理或新会话；如需独立评审，请授权后由隔离上下文的评审者重做）；结论：**带条件通过**。

规则来源：[设计评审](../../../.agents/skills/finns-delivery-workflow/references/design-review.md)。触发原因：改变身份、权限、会话、持久化与数据迁移；安全边界；与 FINNS-15、FINNS-17 共用契约。无外部服务、无新依赖、无第三方额度。

输入：[需求修订2](../../requirements/FOUNDATION_USER_ADMIN_REQUIREMENTS.md)、[R3 记录及确认](PROTOTYPE_USER_ADMIN_R3.md)、[验收映射](ACCEPTANCE_USER_ADMIN.md)、当前源码（`access/*`、`user/AuthController`、`account/*`、`V12`/`V13`）。

## 抽查的关键主张

| # | 主张 | 核对方法 | 结果 |
| --- | --- | --- | --- |
| 1 | 创建登录会话只有一处，所以只需在登录处挡停用账号 | 对 `src/main/java` 搜索 `setAttribute(`：仅 `AuthController.login` 写 `USER_ID`；`AccountController` 只更新 `AUTH_EPOCH` | **成立** |
| 2 | 身份只经 `AccessService.resolve` 与 `AuthController.requireUser` 读取，所以两处加停用检查即覆盖 | 搜索 `USER_ID` 读取点；`PermissionInterceptor` 仅用它选 401 文案 | **成立** |
| 3 | 密码重置不建立会话，停用账号完成重置不会变相登录 | 读 `AccountPasswordService.reset`、搜索 `account` 包 `setAttribute` | **成立**；账号流程查询用户时无状态过滤（`AccountLinkService`、`AccountPasswordService` 全部 `user_accounts` 语句已逐条看过），找回流程无需改 |
| 4 | 所有角色/权限/分配写操作都先锁 `access_control_state` | 读 `AccessAdminService`：`assignRole` 调 `lockVersion`，其余四个写方法调 `checkVersion`（`for update`） | **成立**；本项新增写方法沿用同一把锁 |
| 5 | 请求入口读取的操作者身份可能在锁内已过期（并发转交），所以锁内必须重读 | 读 `AccessService.current`（请求内缓存）、`PermissionInterceptor` 仅检查权限不加锁 | **成立**：此前不存在“站长”概念，该竞态是本项新引入；设计已要求锁内重读，由 UA-A15 并发测试覆盖 |
| 6 | 新增 `OWNER` 角色不影响“注册默认角色/管理员”查找 | 读 `AccessService.defaultRole`（`system_kind='DEFAULT'`）、`AccessBootstrap`、V12 唯一部分索引 | **成立** |
| 7 | PostgreSQL 中 `roles.system_kind`、`access_audit_log.type/action` 的内联 CHECK 约束名为 `<表>_<列>_check`，迁移用该名删除 | 迁移尚未执行 | **未核实**：转入 G6（C-02），在隔离 PG 库用 `pg_constraint` 核对并跑迁移 |
| 8 | 回退到旧包会让停用账号重新可登录 | 旧包没有读取 `account_status` 的代码（V13 之前/之后的 `AuthController.login` 均不检查） | **成立**（按源码推断；未实际回退演练） |

## 逐维度

| 维度 | 结论 | 依据 | 问题/建议 |
| --- | --- | --- | --- |
| 1 需求覆盖与原型一致 | 满足 | 契约 §4、§10 逐条映射 UA-R01–R15、UA-A01–A15；§1 列 6 项偏差，均不改用户可见流程 | 建议：D2（管理员改自己的角色）文案更准确，已记录 |
| 2 方案取舍 | 满足 | 站长：独立角色+指针（否决布尔列、仅指针、固定首位）；并发：全局行锁（否决行锁排序、SERIALIZABLE）；会话：复用 epoch（否决会话表） | 无 |
| 3 现状核对 | 满足 | 抽查 1–6 成立 | 无 |
| 4 数据与迁移 | 有问题 | V14 全部附加/放宽；但生产迁移指定站长有产品含义；回退会使停用失效 | 重要：C-01、C-03、C-02（见下） |
| 5 安全与隐私 | 满足 | 身份取自会话；写接口要 CSRF（沿用）；本人只看到“账号已停用”不见原因；记录不含凭据；公开提示不枚举状态 | 建议：邮箱核对被明确声明为防误选而非再认证，设计未夸大 |
| 6 并发与一致性 | 满足 | 全局锁串行化；“正常管理者”在锁内计算；重复提交幂等（目标状态已达成直接 200） | 重要（验证）：并发场景必须在 H2 与 PG 都有测试（C-04 已并入测试映射） |
| 7 失败模式与运维 | 满足 | 数据库异常→503 并保留输入；记录失败只记日志；无外部依赖 | 建议：拒绝记录可被有权限者刷屏——已记为已知局限 |
| 8 外部服务与成本 | 不适用 | 无外部服务 | — |
| 9 可测试性 | 满足 | 契约 §10 每条验收有测试；PG 并发与迁移单列；真人/多设备单列为未验 | 无 |
| 10 范围与门禁 | 满足 | 无新依赖/范围；站长初始化默认值在 §12 单列为待用户决定，未被设计默认掉 | 无 |

## 需用户决定

1. **生产迁移时谁成为站长**。已由用户决定（USER-ADMIN-D13）：用户提供的账号，经部署配置邮箱指定。
2. **回退策略**：已由用户决定不支持回退到旧包（USER-ADMIN-D13）。

| 编号 | 级别 | 条件 | 去向 | 证据或登记位置 |
| --- | --- | --- | --- | --- |
| C-01 | 重要 | 生产站长指定需用户确认账号 | 转入 G8 → **已关闭** | 用户提供生产站长账号（USER-ADMIN-D13，邮箱不入库）；启动初始化改为该配置邮箱优先并有测试 `AccessBootstrapOwnerEmailTests`；发布时仍须按环境变量配置 |
| C-02 | 重要 | 在隔离 PostgreSQL 核对 CHECK 约束名并跑 V13→V14 迁移与重复启动 | 转入 G6 → **已于 G6 关闭** | [实施记录 §3](IMPLEMENTATION_USER_ADMIN.md)：空库迁移到 V14、`pg_constraint` 约束名核对、V13 复制库升级演练、预览重启重复启动均成功 |
| C-03 | 重要 | 回退会使停用失效：发布时记录停用账号清单并决定处置 | **明确不采纳**（用户决定不支持回退到旧包，USER-ADMIN-D13） | 概设 §4；契约 §12；作为已知局限保留 |
| C-04 | 重要 | 并发（互相停用、与角色/权限竞争、并发转交）测试覆盖 H2 与 PG | 转入 G6 → **已于 G6 关闭** | `UserStatusTests`/`OwnerTransferTests` 的并发用例在 H2 与 PostgreSQL 隔离库均通过；“管理员互相停用”因层级规则已不可发生，改测多操作者同时停用同一成员与并发转交 |
| C-05 | 建议 | 拒绝记录可被有权限者刷屏 | 明确不采纳（已知局限） | 概设 §5；操作者须有 `admin.users`，行为可追责；不引入限流以免扩大范围 |
| C-06 | 建议 | V14 中 `OWNER` 权限列表显式写 11 个权限码，不依赖 `ADMIN` 现状 | 关闭 | 契约 §2 已按此实施 |

C-02/C-04 已在 G6 关闭；C-01 已按用户决定关闭，C-03 经用户决定明确不采纳；C-05 为已知局限；C-06 在契约中关闭。无遗留转入下游的条件。

## 对已通过门禁的影响

不改变 G0–G2 已确认范围与 R3；不重开 FINNS-15 的 G4–G7（仅在登录处与会话解析处各加一条停用检查，行为对未停用账号不变，由 FINNS-15 既有测试回归覆盖）。
