## 未比较备选的决定（同作者自评反向检查）

逐个列出设计中我选择但未充分比较的点：(a) 草稿表与公开行的**同一行更新**（vs 每次发布新建行并重定向旧ID）——旧ID/评论/点赞/专题引用必须保留，新建行方案会破坏它们，用户可感知结果相同点只有“旧链接可用”，已作为设计理由记录；(b) 保存与检测的事务顺序——用户可感知（检测失败时草稿是否保留），需求已明确“保留稿件”，非自选；(c) 新路径前缀`/api/me/articles`——对用户不可感知；(d) 客户端渲染而非服务端渲染——用户不可感知，但影响搜索引擎/分享预览：当前站点为SPA，无服务端渲染，与现状一致；若以后需要分享预览另议。除D1–D5外未发现需补充的用户可感知备选。
